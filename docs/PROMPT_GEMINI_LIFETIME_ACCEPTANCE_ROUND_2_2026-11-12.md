# Gemini: закрыть замечания второй приёмки lifetime

## Цель и чтение

Локально устранить преобразование неизвестного оборота в ноль, проверить stale-обновление уже синхронизированной карты и уточнить доказательства. Читать `AGENTS.md`, `CLAUDE.md`, `docs/OWNER_LIFETIME_TURNOVER_UPDATE_2026-11-12.md`, `docs/CONTRACT_LIFETIME_TURNOVER_2026-11-12.md`, последний раздел `reports/LIFETIME_TURNOVER_CURATOR_REVIEW_2026-11-12.md`, свои отчёты агента/форм. Существующее dirty tree сохранить.

## Разрешённая работа

1. Зафиксировать baseline адресных тестов проектным Python. Не использовать неизвестный системный интерпретатор.
2. В `one_com_source.py` различить числовой ноль из корректного результата `ЕСТЬNULL` и отсутствующий/неизвестный COM-результат `Оборот`. Последний не превращать в `0`: передавать неизвестное по текущему контракту либо безопасно отклонять недостоверное чтение с обезличенной диагностикой. Не менять баланс и другие поля ради обхода проблемы.
3. Добавить тест worker-пути для числового нуля, положительного значения, `None` и отсутствующего атрибута. Показать, что неизвестное не заменяет известный оборот нулём. Отрицательный оборот и выключенный флаг сохранить по контракту.
4. Дополнить `test_runtime_stale_retry.py` сценарием существующего committed HMAC: прежний оборот подтверждён; меняется только оборот; первая отправка stale; неизменившийся источник перечитывается; после продвижения времени оборот доставлен; следующий цикл ничего не отправляет. Состояние/HMAC не сбрасывать, прошлый committed хеш не удалять для искусственного успеха. Использовать настоящие runtime/StateStore/OneComLoyaltySource; обозначить имитации COM/Cloud.
5. В §4.1 контракта уточнить: отвергнутый новый хеш не фиксируется, но предыдущий committed хеш может оставаться. Не называть mock Cloud настоящим backend и не обещать проверенную интеграцию с ONE.
6. Неблокирующая правка admin: локализовать русский placeholder «Бессрочно / без предела» в KK-форме статуса через существующий i18n. Не менять прочие поля и дизайн заново. Для точной визуальной приёмки акции дополнить отчёт снимком именно `offer`, а не только «Новый баннер»; использовать существующий локальный mock-контур, без production.
7. Выполнить адресные и полные тесты агента, адресные admin-тесты и lint/typecheck затронутого frontend; записать полные результаты и предупреждения в обновлённые отчёты. Известное предупреждение Node о `--localstorage-file` зафиксировать отдельно, не менять среду ради его подавления.

## Ограничения и критерии

`backend/` и `mobile/` не изменять. Флаг агента оставить выключенным. Реальную ONE, Windows-службу, KONS2 и production не трогать; EXE/APK не собирать; commit/push/deploy не выполнять. Не реализовывать возвраты/PDF за владельца, не сбрасывать SQLite/курсоры/HMAC, не раскрывать секреты и персональные данные.

Критерии: неизвестное не становится нулём; прежний HMAC совместим; stale существующей карты не теряет изменившийся оборот; контракт честно называет уровень доказательств; KK-placeholder переведён. Обновить `reports/LIFETIME_TURNOVER_AGENT_2026-11-12.md` и при необходимости `reports/LIFETIME_FORMS_ADMIN_2026-11-12.md`, затем СТОП для приёмки.

Правило: «Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть». Исключение только для заранее заданного red→green: новый тест на `None`/отсутствующий атрибут можно сначала показать падающим, затем исправить ровно эту причину и повторить его. Неверный путь чтения разрешено уточнить через `rg --files` без продуктовых изменений. Другие ошибки не дают разрешения на ремонт окружения.
