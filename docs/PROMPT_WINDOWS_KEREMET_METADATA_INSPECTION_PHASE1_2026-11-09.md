# Задание: Инспекция метаданных 1С Keremet (Фаза 1: Среда и Метаданные, Rework 3 Final) — 2026-11-09

> **СТАТУС: Принято куратором 2026-11-09 для одного запуска Фазы 1 уполномоченным оператором на Windows Keremet. Только чтение метаданных. Windows/COM/DPAPI на клиенте ещё не проверены; при ошибке — СТОП, без повторного запуска.**

**Где выполнять:** на Windows-компьютере с **боевой базой 1С POSCENTER ONE магазина Keremet** (НЕ KONS2 / int).
**Исполнитель:** уполномоченный специалист (локальный оператор / администратор) с доступом к серверу Keremet.
**Инструмент:** проверенный изолированный скрипт `docs/tools/keremet-inspection/inspect_metadata.py`.
**Окружение:** PowerShell, Python 32-bit (`x86`) с библиотекой `pywin32`.

---

## Важнейшие правила безопасности

1. **Строго READ ONLY.**
   Никаких запросов записей (чеков, движений, карт). Запрещено создание, проведение, удаление документов, изменение конфигурации и регистрация COM (`regsvr32`).
2. **Службу и состояние агента не трогать.**
   НЕ останавливать и НЕ перезапускать службу `POSCENTERLoyaltyAgent`.
   НЕ изменять и НЕ открывать на запись каталог `C:\ProgramData\POSCENTER\LoyaltyAgent\state\` (`agent_state.db`, `agent_state.key`, `agent.lock`).
3. **Архитектура с гарантированным завершением по таймауту (Supervisor Process):**
   Инспектор запускается в режиме супервизора, который управляет отдельным дочерним рабочим процессом. При превышении таймаута (25 с) супервизор принудительно завершает **только свой дочерний процесс** через `terminate()` / `kill()`. Процессы службы агента не затрагиваются.
   *(Примечание: завершение клиентского COM-процесса прерывает локальное ожидание, но не гарантирует немедленной отмены зависшей операции на стороне сервера 1С, если таковая возникнет. При этом в Фазе 1 выполняются только вызовы чтения метаданных, а не тяжёлые запросы к БД).*
4. **Изолированный каталог вывода с уникальным суффиксом и проверка записи:**
   Каждый запуск создаёт уникальную директорию `C:\cashback-inspection\keremet-turnover\run_<YYYYMMDD_HHMMSS_ffffff>_<token>\` без риска перезаписи прошлых отчётов (`exist_ok=False`).
   При любом сбое сохранения файлов отчёта (`metadata_report.json`, `metadata_report.md`) скрипт не маскирует ошибку успехом: операция прерывается с ошибкой `ERR_REPORT_WRITE_FAILED` и ненулевым кодом выхода (1 или 2).
5. **Точный парсинг конфигурации `.env.service`:**
   Парсер полностью соответствует логике инсталлятора Inno Setup (`config_serializer.iss:86-114`) и `python-dotenv`: снимаются внешние кавычки, и восстанавливаются экранированные обратные слэши (`\\` $\to$ `\`), корректно обрабатывая сетевые UNC-пути (`\\server\share`), локальные пути и кириллицу.
6. **Барьер целевого бизнеса и явное подтверждение оператора:**
   Автоматической проверки принадлежности базы бизнесу нет (в метаданных 1С и в файловом пути такое имя может отсутствовать). Поэтому оператор **обязан явно подтвердить**, что находится на боевом сервере Keremet, передав флаги:
   `--business-slug keremet --confirm-target-operator`.
   Встроенный локальный барьер скрипта дополнительно защищает от случайного запуска на известной тестовой базе (`C:\1C_data\int`), возвращая ошибку `ERR_PRECHECK_TEST_TARGET_BLOCKED`.
7. **Секреты и персональные данные скрыть:**
   Скрипт содержит строгий закрытый список кодов ошибок (allowlist). Значения паролей, строк подключения, DPAPI-ключей и пути к базе **никогда не выводятся в консоль и не попадают в отчёты**.
8. **Обязательное правило:**
   **«Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть»**.

## Необходимые предпосылки (Prerequisites) на сервере Keremet

Перед запуском убедитесь:
1. **Python 32-bit (x86):** 1C:Предприятие 8.3 COMConnector (`V83.COMConnector`) на клиенте зарегистрирован как 32-битный In-Proc Server DLL. Запуск из 64-битного Python завершится ошибкой `ERR_PRECHECK_PYTHON_ARCH_NOT_X86`.
   Используйте 32-битный Python агента (например, `C:\cashback-venv\Scripts\python.exe`).
2. **Пакет `pywin32`:** в виртуальном окружении установлены модули `win32com` и `pythoncom`.
3. **Права доступа:** оператор должен иметь права на чтение конфигурационного файла:
   `C:\ProgramData\POSCENTER\LoyaltyAgent\config\.env.service`.
   *Если прав недостаточно (ошибка `ERR_PRECHECK_CONFIG_ACCESS_DENIED`) — СТОП. Не ослабляйте DACL файла, запуск должен производиться уполномоченным администратором.*
4. **Явные флаги целевого бизнеса:**
   Без явных флагов `--business-slug keremet` и `--confirm-target-operator` скрипт завершается с ошибкой `ERR_PRECHECK_OPERATOR_CONFIRMATION_REQUIRED` или `ERR_PRECHECK_BUSINESS_SLUG_REQUIRED`.

---

Не устанавливать Python/pywin32, не регистрировать COM и не менять права ради этого запуска. Если согласованных runtime или прав нет — СТОП с безопасным кодом/описанием prerequisite. До запуска оператор локально подтверждает, что конфиг указывает на настоящую ONE Keremet; строку подключения, путь базы и секреты в чат не передавать. Общий параметр `--business-slug` этого сам не доказывает.

```powershell
New-Item -ItemType Directory -Path "C:\cashback-inspection\keremet-turnover" -Force | Out-Null
Set-Location "C:\cashback-inspection\keremet-turnover"
```

### Шаг 2. Копирование инструмента инспекции

Скопируйте проверенный файл из репозитория:
`docs/tools/keremet-inspection/inspect_metadata.py` $\to$ `C:\cashback-inspection\keremet-turnover\inspect_metadata.py`

Проверьте файл перед запуском. Ожидаемый SHA-256 проверенной версии: `97faf7be72f16fb6183833feffc24b1f8a34cdffcf2d514911deef80642b6cf7`. При несовпадении — СТОП.

Проверка SHA-256:
```powershell
(Get-FileHash -Algorithm SHA256 C:\cashback-inspection\keremet-turnover\inspect_metadata.py).Hash
```

Размер файла:
```powershell
(Get-Item C:\cashback-inspection\keremet-turnover\inspect_metadata.py).Length
```

### Шаг 3. Запуск инспекции Фазы 1

Запустите скрипт через 32-битный Python с обязательными флагами бизнеса и подтверждения оператора:

```powershell
& "C:\cashback-venv\Scripts\python.exe" C:\cashback-inspection\keremet-turnover\inspect_metadata.py --business-slug keremet --confirm-target-operator
$LastExitCode
```

**Ожидаемый вывод при успехе (Exit Code 0):**
```text
[HH:MM:SS] === START: Keremet Metadata Inspection Phase 1 Supervisor ===
[HH:MM:SS] Output directory: C:\cashback-inspection\keremet-turnover\run_...
0
```

### Шаг 4. Сбор результатов

Скрипт формирует отчёты в уникальной папке запуска:
- `metadata_report.json`
- `metadata_report.md`

Передайте куратору содержимое `metadata_report.md` (или JSON).
В отчёте зафиксированы:
1. Состав реквизитов справочника `БонусныеКарты` (или аналогов).
2. Наличие и состав регистра `ОстаткиБонусныхКарт` (измерения, ресурсы, реквизиты, включая `СуммаЧека`).
3. Наличие регистров продаж (`Продажи`, `ОборотыБонусныхКарт`).
4. Состав документов розницы (`ОтчетКассовойСмены`, `ОтчетОРозничныхПродажах`).

*(Примечание: отсутствие совпадений в отсканированном наборе метаданных означает отсутствие объекта среди проверенных коллекций конфигурации, но не заменяет экспертный анализ структуры 1С).*

## Обработка нештатных ситуаций
- `Exit Code 1`: ошибка предпосылок (`ERR_PRECHECK_*`, включая блокировку тестовой базы или отсутствие подтверждения оператора), сбой подключения к 1С (`ERR_COM_*`) или сбой сохранения отчёта (`ERR_REPORT_WRITE_FAILED`). СТОП, проверьте безопасный код ошибки в выводе консоли или отчёте. Не меняйте пароли и настройки вручную.
- `Exit Code 2`: таймаут 25 секунд (`ERR_METADATA_TIMEOUT`) либо сбой сохранения отчёта по таймауту (`ERR_REPORT_WRITE_FAILED`). Дочерний рабочий процесс был автоматически принудительно завершён супервизором (`terminate()` / `kill()`). СТОП, повторный запуск не производить.
- `Exit Code 3`: ошибка чтения метаданных (`ERR_METADATA_*`). СТОП, обход коллекций был прерван для защиты от непредвиденных сбоев.
