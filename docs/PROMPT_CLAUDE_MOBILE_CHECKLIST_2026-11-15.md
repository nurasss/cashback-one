## Подготовка

1. В RU на пропуске заставки написать **«Пропустить заставку»**, KK — соответствующий перевод.
   Сохранить весь переход native splash → fullscreen → выход без вспышки главной,
   watchdog, доступность и отсутствие повторного показа на каждом возврате.
2. Перепроверить единым набором: розовые тексты/иконки, выход, отсутствие упоминания 14 дней,
   сохранение токенов при обновлении, период истории, ссылки, 6 акций/раскрытие, формат сумм,
   переход к магазинам/расстояния, отсутствие калькулятора, статический QR и push-код.
3. Проверить каталог статусов с реальным опубликованным backend и кэшем:
   смена версии/ETag, обновление при возврате и ручном refresh, принадлежность бизнесу,
   offline fallback. Для изменяющего контент E2E использовать согласованный тестовый scope,
   не менять production-проценты Keremet ради скриншота.
4. Сохранить минимальный статус/процент каталога при неподтверждённом личном статусе,
   приоритет подтверждённых персональных данных, корректные 0%, неизвестный оборот не делать нулём.
5. Не объявлять сессию 365 дней или личный lifetime-расчёт внедрёнными только по APK:
   подтвердить совместимую серверную версию отдельным отчётом backend.
6. Названия/пороги/проценты брать из каталога, пример 350/700 тысяч и 1/3/5% не зашивать.
   Карта выбора «Другого города», динамический QR и WhatsApp-код списания — отменены.

Если «Roboto в приложении» в старом блоке относится именно к Android, это конфликт с
принятым Montserrat: установить контекст исходного задания до смены шрифта, не менять всю
типографику по одному неоднозначному заголовку. Не угадывать зачёркнутое на ненайденном образце.

## До сборки

- Полный diff, typecheck/lint, адресные и полные mobile-тесты. Baseline-ошибки не скрывать.
- Показать куратору RU/KK и светлую/тёмную тему: главная, статус, магазины, профиль,
  ошибки/пустой каталог, обновление данных. Для заставки нужен весь переход, не стоп-кадр.
- Явно подписать платформу: web-demo не Android. Сначала визуальная приёмка; новую сборку
  ради проверки очевидного текста владельцу не отправлять.
- СТОП на независимую приёмку исходников и демонстрации. Поручение завершить выпуск уже дано,
  но оно не заменяет эту проверку.

## После приёмки: один выпуск

Сверить актуальные версии/артефакты; не перезаписывать 1.0.25. Выбрать следующий свободный
versionName/versionCode, согласованно обновить штатные файлы и собрать скриптом клиента Keremet.
Не запускать destructive prebuild. Сохранить пакет, ключ подписи и production API,
demo выключен; разрешения не расширять без необходимости.

Проверить подпись/сертификат, версии, состав, ресурсы и фактический бандл. Публиковать
только принятый APK; сначала файл и обратный SHA-256, затем только `keremet-version.json`.
Сохранить старый APK/manifest и откат. Общий manifest и лендинг не переключать.
Если учётные данные доступны только владельцу — защищённый ввод, не чат/аргументы процесса.
На устройстве при наличии доступа: обновление поверх старой версии без повторного входа,
полный переход заставки, каталог после изменения, QR/push. Без устройства честно отметить предел.

Не менять admin/агент/ONE, бонусы/проценты кассы, GitHub Releases; без отдельного поручения
не делать commit/push. **Упало или неожиданно — СТОП и безопасный сырой вывод; без
самостоятельных исправлений и повторных мутаций.** Не выводить секреты и ПДн.

исходники/тесты, визуальная приёмка, APK, публикация, реальный Android, незакрытые ID аудита.
