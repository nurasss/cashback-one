## Что сделать

1. **Интервал по умолчанию 60 секунд.** `config.py` (`agent_poll_interval_seconds`) и установщик (`agent/packaging/config_serializer.iss`, сейчас `AGENT_POLL_INTERVAL_SECONDS='300'`). При обновлении с сохранением настроек: если в `.env.service` стоит ровно `300` (старое значение по умолчанию) — заменить на `60`; любое другое значение не трогать. Остальные строки `.env.service`, DPAPI-значения, ACL — без изменений. Покажи `git diff` установщика.
2. **Забор команд.** После каждого успешного heartbeat агент вызывает `claim`. Если сервер отвечает 404 (старый сервер) — тихо (уровень DEBUG) и без ошибки агента; другие ошибки — как временная ошибка сети, без остановки службы.
3. **`sync_now`:** немедленно разбудить цикл синхронизации (не ждать интервала; если цикл уже идёт — следующий сразу после него). После окончания цикла — `complete` со `completed` или `failed` и коротким текстом ошибки без ПДн.
4. **`full_resync`:** отправить в облако **все** карты текущего снимка ONE, не глядя на сохранённые хеши, и операции за весь период первичной загрузки (`agent_one_initial_history_days`). Повторная отправка безопасна: сервер не создаёт дублей (`uq_cards_business_barcode`, `uq_transactions_card_external`). **Файлы состояния не удалять**, HMAC-ключ не менять; текущий курсор операций после полной синхронизации не должен откатиться назад (он остаётся не меньше прежнего). Опиши, как это сделано. Если без сброса состояния не обойтись — СТОП с описанием.
5. Одновременно выполняется одна команда; команды не теряются при временной ошибке сети (повтор `complete`).
6. В журнал: `Command received: type=… id=…`, `Command completed: type=… status=…` (без ключей и ПДн). Описать в `docs/AGENT_DIAGNOSTICS.md`.
7.
