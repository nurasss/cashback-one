# Инструкция по установке, обновлению и откату POSCENTER Loyalty Agent (версия 0.4.0)

## 1. Новая установка (0.4.0)

1. Запустите установщик `CashbackOneAgent-Setup-0.4.0.exe` с правами администратора.
2. На странице «Настройка подключения к облаку»:
   - Укажите URL облака (HTTPS в production).
   - Введите секретный ключ агента (`Agent API Key`, от 16 символов).
3. На странице «Подключение к базе POSCENTER ONE»:
   - Укажите путь к файловой базе 1С (каталог с файлом `1Cv8.1CD`).
   - Укажите имя пользователя 1С (только чтение).
   - Введите пароль пользователя 1С.
   - Нажмите кнопку **«Проверить подключение»**. Установщик запустит команду `check-one` в фоновом режиме через исполняемый файл агента (совпадающая разрядность с COM-соединителем) и выведет статус:
     - `Подключение к 1С успешно установлено.`
     - либо понятное сообщение об ошибке (`com_not_registered`, `db_not_found`, `auth_failed`, `db_locked`, `timeout`, `unknown`).
   - Если проверка не была запущена или не прошла успешно, при нажатии «Далее» установщик запросит подтверждение: *«Подключение к 1С не проверено. Продолжить установку?»*.
4. На странице маппинга укажите проверенный файл `stage0_mapping.json`.
5. По завершении установки:
   - В файл `%ProgramData%\POSCENTER\LoyaltyAgent\config\.env.service` записываются **зашифрованные** через Windows DPAPI значения: `AGENT_API_KEY_DPAPI` и `ONE_PASSWORD_DPAPI`. Открытый ключ и открытый пароль на диске не сохраняются.
   - Интервал опроса по умолчанию (`AGENT_POLL_INTERVAL_SECONDS`) составляет **60 секунд** (синхронизация раз в минуту).
   - Права на каталог и файл фиксируются через защищённый DACL: доступ имеют только `NT AUTHORITY\SYSTEM` и `BUILTIN\Administrators`.
   - Служба `POSCENTERLoyaltyAgent` регистрируется и автоматически запускается (режим `delayed-auto`).

## 2. Чистая установка на компьютере другого бизнеса

> [!IMPORTANT]
> **У каждого клиента свои бизнес, ключ, ONE и состояние.** Нельзя переключать существующую SQLite на другого клиента/базу без процедуры миграции.
> Если на компьютере ранее был установлен агент другого бизнеса:
> 1. Остановите службу `POSCENTERLoyaltyAgent`, если она запущена (`Stop-Service POSCENTERLoyaltyAgent`).
> 2. **До установки** перенесите (или переименуйте) всю папку `C:\ProgramData\POSCENTER\LoyaltyAgent` в защищённую резервную копию (например, `C:\cashback-stage0\backup_previous_business_<timestamp>`).
> 3. Запустите установщик `CashbackOneAgent-Setup-0.4.0.exe` и выполните чистую установку с новыми ключами, пользователем и маппингом. При установке будет создана новая база состояния `agent_state.db` и сгенерирован уникальный HMAC-ключ `agent_state.key` для нового бизнеса.

## 3. Обновление с сохранением настроек (0.2.2 / 0.3.0 → 0.4.0)

1. Перед запуском обновления создайте резервную копию каталогов `%ProgramData%\POSCENTER\LoyaltyAgent\` (или бэкап `C:\cashback-stage0\backup_upgrade_0_4_0_<timestamp>`).
2. Запустите `CashbackOneAgent-Setup-0.4.0.exe`.
3. На первом шаге выберите вариант **«Сохранить существующие настройки»**:
   - При необходимости замены ключа агента (например, после перевыпуска ключа в кабинете администратора) введите его в поле **«Новый ключ агента»** (поле необязательное; если оставить пустым — текущий ключ сохраняется).
   - При необходимости смены пароля 1С введите новый пароль в поле **«Новый пароль 1С»** (поле необязательное; если оставить пустым — текущий пароль сохраняется).
   - Рядом доступна кнопка **«Проверить подключение»**, позволяющая протестировать соединение с 1С.
4. Нажмите «Далее». Установщик:
   - Считывает существующий файл `.env.service`.
   - Если в параметре `AGENT_POLL_INTERVAL_SECONDS` стоит старое значение по умолчанию (`300`) — заменяет его на `60` (интервал 1 минута). Любые другие значения интервала сохраняются без изменений.
   - Шифрует открытые значения `AGENT_API_KEY` и `Pwd=` из `ONE_CONNECTION_STRING` с помощью DPAPI на месте (при обновлении с 0.2.2).
   - Сохраняет все остальные параметры и комментарии побайтно без изменений.
   - Запись выполняется через временный файл с немедленным применением защищённого DACL.
   - База контрольных точек (`agent_state.db`), HMAC-ключ (`agent_state.key`) и маппинг не затрагиваются.

## 4. Команды из кабинета администратора (версия 0.4.0)

Начиная с версии 0.4.0 агент забирает команды управления из облака после каждого успешного heartbeat (`POST /agent/commands/claim`):

1. **«Синхронизировать сейчас» (`sync_now`):**
   - Немедленно пробуждает цикл синхронизации, не дожидаясь минутного интервала.
   - Если цикл синхронизации уже выполняется в данный момент, следующий внеочередной цикл запускается сразу после его завершения.
   - По окончании цикла агент отправляет на сервер подтверждение (`completed` либо `failed` с текстом ошибки).

2. **«Полная синхронизация» (`full_resync`):**
   - Отправляет в облако **все** карты текущего среза ONE, не глядя на сохранённые локальные хеши.
   - Отправляет операции за весь период первичной истории (`agent_one_initial_history_days`), игнорируя фильтр ранее отправленных операций.
   - Повторная отправка безопасна: облачный бэкенд игнорирует или обновляет существующие записи благодаря уникальным индексам (`uq_cards_business_barcode`, `uq_transactions_card_external`).
   - **Файлы состояния не удаляются, HMAC-ключ не меняется.**
   - Курсор операций после полной синхронизации защищён от отката: он остаётся не меньше прежнего значения.

## 5. Внимание: откат на версию 0.2.2

> [!WARNING]
> Версия 0.2.2 не поддерживает параметры `AGENT_API_KEY_DPAPI` и `ONE_PASSWORD_DPAPI`.
> Если после обновления до 0.4.0 потребуется выполнить откат на 0.2.2 (с помощью `CashbackOneAgent-Setup-0.2.2.exe`):
> 1. Откат с выбором «Сохранить существующие настройки» приведёт к тому, что служба 0.2.2 не сможет прочитать зашифрованные DPAPI ключи (вызовет ошибку валидации конфигурации).
> 2. Для корректной работы 0.2.2 после отката необходимо либо:
>    - восстановить исходный файл `.env.service` из резервной копии, созданной перед обновлением;
>    - либо запустить установщик 0.2.2 в режиме перенастройки (если база состояния ещё не была инициализирована), либо вручную указать открытый `AGENT_API_KEY` и пароль в `.env.service`.

## 6. Модель безопасности DPAPI

- **DPAPI с областью машины (`CRYPTPROTECT_LOCAL_MACHINE`)** защищает конфигурационный файл при копировании на другой компьютер и от случайного чтения секретов в резервных копиях.
- **DACL (SYSTEM и Администраторы)** — ключевой барьер доступа на локальном компьютере: от локального администратора и любого процесса с повышенными правами на этом же компьютере защищает только строгий DACL файла и каталога.
- **Соль (энтропия)** не является секретом (репозиторий публичный) и служит исключительно для логического отделения данных агента от других приложений в системе.
