# Gemini: подготовить автономную диагностику метаданных Keremet — 2026-11-09

Владелец уточнил: **на компьютере Keremet нет ИИ-исполнителя**. Не давать владельцу промпт для исполнения там, не требовать Python/pywin32, ручного создания скриптов или консольных команд. Нужен готовый переносимый диагностический EXE и короткая инструкция для человека, который может запустить файл на Keremet.

Прочитать AGENTS.md, CLAUDE.md, `reports/KEREMET_METADATA_PHASE1_ACCEPTED_2026-11-09.md` и принятую Windows-инструкцию Фазы 1. Проверенный скрипт: `docs/tools/keremet-inspection/inspect_metadata.py`, SHA-256 `97faf7be72f16fb6183833feffc24b1f8a34cdffcf2d514911deef80642b6cf7` (при отличии сначала сверить diff, не упаковывать незнакомую редакцию).

**Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть.**

## Что подготовить

1. Автономный Windows x86 EXE на существующей Windows build-среде KONS2 (там уже собирается агент с Python/pywin32/PyInstaller). **Mac не собирает Windows EXE**: если Gemini сейчас работает только на Mac, подготовить сборочные исходники и отдельное самодостаточное задание для имеющегося исполнителя на KONS2, затем остановиться с точным статусом. Не представлять задачу на Windows как уже выполненную сборку и не отправлять её на Keremet.
2. Предпочесть переносимый комплект в ZIP без установщика, службы и Python на клиенте. В составе EXE все нужные runtime/pywin32. Никаких конфигов клиента, ключей, DB, HMAC, Firebase и маппинга в архиве. Не встраивать тестовый ключ/соединение KONS2.
3. Запуск двойным щелчком с простым локальным подтверждением: «Запускается чтение структуры базы ONE магазина Keremet. Продолжить?»; отмена ничего не запускает. Инструмент читает существующий защищённый конфиг локально, не просит/не печатает секреты. При необходимости чтения конфига — стандартный запрос UAC для уже уполномоченного администратора; ACL не менять, пароль в чат не просить. Не пытаться обходить отсутствие прав.
4. Обязательно адаптировать subprocess supervisor для frozen EXE: сейчас `sys.executable` — Python и в argv передаётся путь .py. В frozen-режиме это сам EXE, child должен запускаться с корректным `--worker-mode`, без рекурсии запуска новых supervisor и без секретов CLI/env. Сохранить 25 с и прекращение только своего worker. Самостоятельно не завершать процессы 1С/агента.
5. Только чтение метаданных, без запросов записей/карт/чеков, настройки уровней и расчёта оборота. Службу агента не останавливать, не запускать второй синхронизатор, state/config не менять. На KONS2 к реальной int не подключаться даже ради smoke-проверки.
6. Результат — уникальная папка отчёта; понятное окно/сообщение с местом файла metadata_report.md, при ошибке безопасный код и «Не повторяйте запуск, передайте результат». Без автоматического сетевого отправления. Инструкция для владельца максимум 4–5 действий: распаковать → запустить → подтвердить → передать отчёт. Не утверждать, что конкретный человек уже доступен на Keremet.

## Проверки

Изолированные тесты сборочного wrapper, frozen child command без секретов/рекурсии, отмена, timeout, отсутствие/запрет чтения конфига, безопасные ошибки, запись отчёта. Настоящие config/ONE не использовать. Windows x86 EXE: проверка комплектности и безопасный smoke без подключения, разбор аргументов/самопроверка на синтетической среде. Моки не равны реальной интеграции. Проверить отсутствие клиентских секретов/данных в комплекте.

Если адаптация требует менять принятую логику инструмента — сохранить diff, новые суммы и тесты для повторной приёмки. Приёмка старого Python не является автоматической приёмкой нового EXE.

Без установки EXE на Keremet, запуска на клиенте, commit/push и публичной публикации. Итоговый ZIP/EXE, размеры, полные SHA-256, состав и результаты проверок — `reports/KEREMET_METADATA_EXE_BUILD_2026-11-09.md`. Сам код продукта admin/mobile/backend/агент не менять; это отдельный диагностический комплект в docs/tools и локальных сборочных артефактах вне Git.
