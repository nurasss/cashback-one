## Изменение

В `LandingPage.tsx` шапка использует `/brand-mark.png`, класс `landing-brand-logo`, рядом надпись Cashback One. Нужная готовая иконка — `mobile/assets/icon.png` (красная стеклянная монета с надписью ONE; куратор визуально проверил). Не использовать иконку Keremet и не рисовать новую.

1. Скопировать готовый PNG в `admin/public/` под отдельным именем, например `cashback-one-app-icon.png`; заменить ссылку в шапке публичного лендинга. Не перезаписывать общий brand-mark: он может использоваться кабинетом.
2. Сохранить надпись Cashback One, ссылку на начало страницы и доступное имя. Иконка декоративная рядом с текстом — alt пустой. Сохранить пропорции и чёткое изображение, не обрезать монету, не добавлять рамку или фон. Размер согласовать с текущей шапкой, не увеличивать её высоту.
3. Аналогичную публичную шапку страницы «не найдено» в том же файле привести к той же иконке. Футер POSCENTER, favicon, логотип входа и кабинета не менять.
4. Публичный лендинг RU/KK на 320, 390 и 1366 px: иконка загружается, название и вход не обрезаны, меню и ссылки работают. Проверить именно страницу проекта, не отдельно нарисованный HTML. Снимки — `reports/landing-app-icon-2026-11-09/`.

## Ограничения и проверка

Не менять mobile, backend, агент, тексты, APK-ссылку, version.json, бизнес-логику, оформление кабинета. Не откатывать параллельные изменения Gemini по упрощению клиентского кабинета. Никакого deploy, commit/push на этом этапе.

Проверки: diff только своей части, совпадение SHA-256 копии PNG с исходником, `git diff --check`, `npm run typecheck` в admin. Перед build проверить `df -h /` (меньше 1 ГБ — СТОП); выполнить `npm run build`, если нет обнаруженного блокера. Новые тесты ради простой замены картинки не нужны. Если параллельная работа мешает сборке, зафиксировать это без исправлений чужого кода.
