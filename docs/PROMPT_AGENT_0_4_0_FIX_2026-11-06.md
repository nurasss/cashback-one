## Ошибка 1: полная синхронизация операций зацикливается на первой странице

`runtime._sync_transactions_stream(full_resync=True)`: после страницы, чей `next_cursor` (`TxPageCursor`, позиция внутри старого окна) «не впереди» сохранённого курсора, в состояние записывается `saved_prev_tx_cursor` (`TxDoneCursor`). На следующей итерации `current_cursor = state_store.get_cursor("transactions")` = этот `TxDoneCursor` → в `OneComLoyaltySource.fetch_transactions` ветка `TxPageCursor` не срабатывает, а при `_full_resync_tx=True` снова выполняется **новый запрос окна с начала** → снова первая страница. Так до 10 000 страниц. У KeremEt 8067 операций — страниц больше одной, ошибка сработает. Тесты на `FakeLoyaltySource` (числовые курсоры) этого не ловят.

Исправить так, чтобы:
- во время полной синхронизации листание шло по **своему** курсору страниц (держать его в памяти цикла), а в состояние агента до конца прохода записывался только курсор, который **не позади** прежнего (или прежний);
- после последней страницы в состоянии — курсор не позади прежнего;
- при обрыве посреди полного прохода (ошибка сети) состояние осталось не позади прежнего, а следующий обычный цикл работал как раньше.

Тест **на `OneComLoyaltySource` с поддельным COM** (как в существующих тестах источника): 3+ страницы операций, прежний курсор — в конце окна; полный проход отправляет все страницы ровно по разу, без повторов первой; итоговый курсор не позади прежнего; обрыв на 2-й странице.

## Ошибка 2: после команды пропадает пауза при ошибках

`_sleep_cancellable` теперь просыпается по `_sync_trigger_event`, а событие сбрасывается только после **успешного** обычного цикла. Если пришла команда и цикл падает (нет связи с облаком, 1С недоступна), каждая пауза после ошибки сразу заканчивается — агент долбит 1С и облако без задержки.

Исправить: сбрасывать событие, когда команда взята в работу (или перед любой паузой после ошибки), чтобы паузы после ошибок соблюдались; новая команда по-прежнему будит ожидание интервала. Тест: команда + постоянная ошибка цикла → между попытками выдерживается задержка `retry_state`.
