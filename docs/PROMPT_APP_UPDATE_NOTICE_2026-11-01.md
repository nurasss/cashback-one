Если вышла новая версия, приложение показывает окно с просьбой обновиться, кнопками «Обновить» и «Позже». «Обновить» открывает скачивание в браузере. Обязательный режим закладывается как резерв и включается только значением в файле на сайте.

## Реализация

Новый файл `mobile/src/features/appUpdate.ts`:

1. Константа `VERSION_INFO_URL` с адресом выше.
2. Чистая `parseVersionInfo(value: unknown): VersionInfo | null`. Возвращает `null`, если:
   - не объект;
   - `latest_version` не вида `^\d+\.\d+\.\d+$`;
   - `latest_version_code` или `min_version_code` не целое положительное;
   - `min_version_code > latest_version_code`;
   - `download_url` не совпадает полностью с `^https://cashback-qr\.poscenter\.kz/app/cashback-one-\d+\.\d+\.\d+\.apk$`. Это защита: при подмене файла приложение не откроет чужую ссылку. Других адресов не допускать.
3. Чистая `updateDecision(info: VersionInfo | null, currentCode: number | null): 'none' | 'optional' | 'required'`:
   - `info` или `currentCode` пустые: `none`;
   - `currentCode < min_version_code`: `required`;
   - `currentCode < latest_version_code`: `optional`;
   - иначе `none`.
4. `fetchVersionInfo(fetcher = fetch)`: GET с таймаутом 5 с через `AbortController`, заголовок `Cache-Control: no-cache`. Разбор тела в `try`. **Любая ошибка даёт `null`, без исключений и журнала.** Запрос идёт не через `ApiClient`: токена в нём быть не должно.

Номер текущей сборки: `Constants.expoConfig?.android?.versionCode` из `expo-constants`. Новые зависимости не добавлять, `expo-application` не ставить. Не число: `null`, окна нет.

Новый компонент `UpdateNotice` в `mobile/src/features/UpdateNotice.tsx`:

- Проверка только при `Platform.OS === 'android'` и `!DEMO_ENABLED`. В вебе и demo компонент ничего не запрашивает.
- Запрос при монтировании и при возврате из фона (`AppState` → `active`), но возврат из фона запрашивает не чаще раза в 6 часов.
- «Позже» скрывает окно до следующего запуска приложения: признак хранится в памяти (`useRef` или состояние), на диск не пишется. Проверка при возврате из фона его не отменяет, если решение осталось `optional`. Если стало `required`, окно показывается.
- Окно: `Modal` с `transparent`, стиль как у других окон приложения, `Button` из `components/ui`. Заголовок, текст, «Обновить», в режиме `optional` ещё «Позже» (`secondary`).
- «Обновить»: `Linking.openURL(info.download_url)` из `react-native`. В `optional` окно закрывается. В `required` остаётся. Ошибка открытия не роняет приложение, окно остаётся.
- `required`: кнопки «Позже» нет, аппаратная кнопка «Назад» окно не закрывает (`onRequestClose` ничего не делает). `optional`: «Назад» работает как «Позже».
- Состояние не обновлять после размонтирования. Подписку `AppState` снимать.

`mobile/app/_layout.tsx`: добавь `<UpdateNotice />` рядом с `<Navigation />` внутри `I18nProvider`. Окно не зависит от входа и показывается и на экране входа. `Navigation`, порядок провайдеров и логика сессии не меняются.
