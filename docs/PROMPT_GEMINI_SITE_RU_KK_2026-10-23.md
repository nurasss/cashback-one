## Реализация

### 1. Общая локализация

- Используй коды `ru` и **`kk`**, для Intl — `ru-RU` и `kk-KZ`; `kz` не является кодом языка.
- По умолчанию русский; сохраняй явный выбор пользователя в отдельном несекретном ключе localStorage. Чтение и запись storage должны переживать запрет доступа и повреждённое/неизвестное значение. Не очищать весь storage, не затрагивать токены или данные авторизации.
- Один согласованный выбор между лендингом, входом и кабинетом; обновление страницы сохраняет выбор.
- Переводы через централизованные, типобезопасные словари; проверь полное совпадение ключей RU/KK. Не переводить через обход DOM, поиск/замену отображённых строк, внешние сервисы или повторные вызовы API.
- Смена языка без перезагрузки, разлогинивания и пересоздания Session/QueryClient; без потери ввода формы, выбранного бизнеса, фильтров, страницы списка, query/hash. Не привязывать ключ корня приложения к locale.
- Публичный лендинг не должен загружать админскую сессию, обращаться к API или тянуть административный JS-чанк/административные словари. Сохрани lazy-границу кабинета. Общий лёгкий механизм языка допустим.

### 2. Переключатель RU / ҚАЗ

- Доступен в шапке лендинга, на странице входа и в кабинете; активный язык явно обозначен и доступен с клавиатуры и для screen reader.
- На 320/390 px не скрывает вход для бизнеса, логотип и основные действия; на маленьком экране можно корректно перенести элементы, нельзя решать проблему `display:none` для входа.
- Сохранить существующий дизайн, сетку, цвета и типографику. Это локализация, не новый редизайн.

### 3. Полнота перевода

Переведи весь отображаемый интерфейс, а не только заголовки:

- Лендинг: навигация, hero, кнопки, переключатель экранов, подписи, alt/aria, инструкции Android, бизнес-раздел, FAQ, footer, публичная 404.
- Вход/авторизация: поля, подсказки, валидация, загрузка, ошибки, завершение сеанса, состояния восстановления и fallback при ошибке загрузки админского чанка.
- Кабинет: навигация, роли, dashboard, бизнесы и детали, формы создания/редактирования, выдача доступа менеджеру, диалоги одноразового показа реквизитов, агенты, карты/операции/покупатели, аудит, контент/акции/уведомления, таблицы, фильтры, пагинация, пустые состояния, подтверждения опасных действий и результаты операций.
- `messageForError`, общие Feedback/DataTable и форматирование дат/чисел. Не менять часовой пояс и смысл диапазонов дат в рамках локализации.
- `document.documentElement.lang`, заголовок страницы и пользовательские описания/доступные имена должны соответствовать выбранному языку. Не придумывать языковые URL или hreflang на несуществующие страницы.
- Не переводить и не менять API-коды, route/resource ID, JSON-поля, enum-значения, GUID, штрихкоды с ведущими нулями, имена магазинов, логины, реальные тексты акций и прочие данные из API. Известные статусы переводить только при отображении. Не выводить сырой серверный текст ошибки или внутренние данные вместо безопасного локализованного сообщения.
- Динамические сообщения со счётчиками и параметрами делать через явную интерполяцию; не собирать грамматику кусками русского текста.
- Проверь глифы Ә Ғ Қ Ң Ө Ұ Ү Һ І и строчные варианты в используемых шрифтах. Не добавлять внешний CDN.
- Существующие скриншоты приложения настоящие и русскоязычные: не рисовать поверх них «переведённые» экраны и не подменять синтетикой. Можно оставить их как есть с честной локализованной подписью о языке демонстрации. Новые настоящие KK-скриншоты — только из изолированного demo web-preview, без изменения production приложения и без реальных данных.
