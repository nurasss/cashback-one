## Контракт и запуск

`GET https://api.cashback-qr.poscenter.kz/public/app-splash?app_id=kz.cashbackone.keremet` до авторизации, без токенов. Другой клиент использует собственный android_app_id из getClientConfig. Поля: enabled, business_id, media_type image|video, media_url HTTPS, width, height, duration_seconds, file_size, version. ETag/304 поддерживаются. enabled=false/нет настройки — обычный запуск, это не ошибка. На последней проверке у Keremet заставка была выключена; на production ничего не включать автоматически.

Использовать реальный контракт, не устаревший пример API-host/media из отчёта: сервер возвращает фактический media_url. Проверять HTTPS, типы/пределы/ожидаемый бизнес и собственный клиент; не подставлять медиа другого клиента. Не требовать наличия карты/авторизации для публичной настройки.

Заставка — экран внутри приложения ПОСЛЕ встроенного native splash, не замена самого первого системного кадра. Две функции: картинка и MP4 H.264 без звука, <=5 с, <=15 MiB (картинка <=5 MiB). Новые видео автоматически muted, никакого звука/loop на стартовом экране. Ресурсы не инвертировать в dark, пропорции сохранять (contain), кнопка «Пропустить» видна и доступна сразу, включая 360px и safe-area.

- Один показ на холодный запуск, не при каждом tab/foreground/ссылке. Фоновую авторизацию/подгрузку не выполнять повторно ради заставки.
- Картинка показывается 2 с с момента готовности; видео — до окончания, максимум 5 с. Ошибка/тайм-аут загрузки/декодирования сразу завершает заставку и открывает обычное приложение, без зависшего чёрного экрана.
- На запрос конфигурации и старт загрузки разумный ограниченный бюджет (например до 2 с каждый), не ждать бесконечно. Без кеша/сети — локальный обычный запуск. Первый онлайн-запуск должен попытаться получить новую настройку, а не всегда пропускать её до второго запуска.
- Кеш по app_id/business/version, ETag, безопасная замена после успешной загрузки. Ограничить размер кеша, не смешивать с токенами и персональным кешем. При disabled удалить/не показывать прежнюю заставку. При временной ошибке допустима последняя подтверждённая заставка своего клиента; описать политику.
- Обновления, push/deep link не должны теряться: после завершения/skip попасть в целевой маршрут. Не показывать UpdateDialog поверх видео; обязательное обновление сохранить, показывать после заставки. При входящем действии во время показа заставку можно завершить.
- Учесть reduce motion: видео можно пропустить в пользу обычного запуска, не создавать искусственную задержку. Обработчики/таймеры/плеер освобождаются при выходе.
