## Что исправить

В `mobile/src/storage/appCache.ts` кеш читается из AsyncStorage асинхронно (`initAppCache()`), а `fetchPromotionsWithCache` и `fetchAppContentWithCache` в `mobile/src/api/app.ts` берут `getCached…()` сразу, **не дожидаясь** загрузки. При холодном запуске без интернета, если чтение AsyncStorage не успело завершиться, сохранённого ответа «нет»: запрос падает, и главная показывает ошибку вместо последних данных. Тесты офлайна кладут данные прямо в память и этот путь не проверяют.

1. В начале обеих функций `await initAppCache()` (ошибка чтения хранилища не должна ломать запрос: сейчас она уже глушится внутри — так и оставить).
2. `clearAppCache()` должна быть надёжной и во время незавершённой `initAppCache()`: после очистки загрузка не должна вернуть старые записи в память (например, дождаться `initPromise` перед очисткой или сбрасывать результат по счётчику поколения).
3. Тесты:
   - холодный запуск: записи лежат только в мок-AsyncStorage (память пуста, модуль загружен заново `jest.isolateModules`/`resetModules`), сеть падает → `fetchAppContentWithCache` и `fetchPromotionsWithCache` возвращают сохранённое;
   - то же с `If-None-Match` из AsyncStorage → 304 → сохранённый ответ;
   - `clearAppCache()` во время незавершённой загрузки → после завершения в памяти пусто.
