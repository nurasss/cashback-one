## 1. Блокер: вставка молча меняет числовое значение

Куратор вызвал текущую normalizeNumericPaste из transpiled исходного NumericInput:

- '-1 000', decimal=true, allowNegative=false → '1000';
- '1,5', decimal=false → '15';
- '1e3 ' → '13';
- '12.34.56 ' → '12.3456'.

Эти строки попадают в ветку handlePaste (содержат пробел или запятую), после чего
цифра подставляется в поле. Нельзя исправлять запрет отрицательных/дробных значений
превращением их в другие положительные/целые числа, удалять буквы, второй десятичный
разделитель и т. п. Это особенно опасно для порога, процента и сортировки.

Нормализовать только однозначный допустимый числовой ввод: согласованные пробелы
разрядов и ОДИН десятичный разделитель для decimal=true. Отрицательное значение
при allowNegative=false отвергать/оставлять на явную валидацию, не менять знак.
При decimal=false дробь не превращать в целое склеиванием цифр. Экспоненты,
несколько разделителей и посторонние символы не «лечить» произвольным удалением.
Не маскировать ошибку последующим clamp/min/max. Невалидная вставка не должна
менять прежнее значение; объяснение/валидация согласованы с текущими формами.
Для корректной вставки не ломать onPaste/onChange и обычную семантику замены.

Добавить regressions helper + реального handlePaste/controlled state. Обязательно
проверить '-1 000', Unicode-минус, '1,5' в integer-поле, '1e3 ', '12.34.56 ',
'1,2,3', а также валидные '90 000', NBSP/narrow-NBSP, '2,5', '2.5', ноль и
отрицательные числа в поле, где allowNegative=true. Подтвердить payload после
валидной/невалидной вставки, не только вызов helper. Backend-защиту не ослаблять.
