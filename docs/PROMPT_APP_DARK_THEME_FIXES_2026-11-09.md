## Замечания

1. **Поздняя загрузка темы перезаписывает явный выбор «Светлая».** `mobile/src/theme/ThemeProvider.tsx:38` проверяет `current === DEFAULT_THEME_PREFERENCE`, что не отличает начальный light от выбранного пользователем light. Сценарий по коду: getItem не отвечает >1,5 с → интерфейс открывается в light → пользователь явно выбирает light (или dark, затем light) → поздний результат getItem со старым dark меняет интерфейс обратно. В хранилище при этом может остаться новый light. Исправить явным учётом выбора пользователем/поколения загрузки, не сравнивать только значение. Добавить тест с управляемым Promise getItem: после тайм-аута сделать явный выбор light, затем вернуть старый dark; новый выбор должен остаться. Покрыть также dark/system и размонтирование. Это вывод из чтения кода, отдельный воспроизводящий тест куратор в продукт не добавлял.

2. **Уточнить план перехода старых APK.** Ограничение «не поднимать общий version.json выше 17» недостаточно: Keremet 1.0.12/13/14/15 имеют более низкие versionCode, а значение 17 уже может предложить им чужой Cashback One APK (порог зависит и от встроенного Constants в конкретной сборке). Убрать формулировку как безопасную гарантию. До инвентаризации поддерживаемых старых APK общий manifest не менять вообще; описать, что любой latest_version_code выше значения, которым пользуется конкретный старый Keremet APK, способен вызвать предложение чужого пакета. При необходимости сверить архивные исходники/отчёты сборок только чтением. Не менять production и не заявлять, что переход всех клиентов подтверждён. Новые сборки с отдельным manifest решают проблему только после их установки.
