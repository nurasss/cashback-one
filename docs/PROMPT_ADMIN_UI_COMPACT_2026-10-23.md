## Задачи владельца

### 1. Громоздкие таблицы показывают 3 строки и разворачиваются

Пример — список в разделе «Карты и клиенты». Сейчас таблица сразу показывает всю страницу (до 25 строк) с пагинацией. Нужно так:

- по умолчанию видны **первые 3 строки**;
- под ними кнопка на всю ширину таблицы: «Показать все (N)», где N — сколько строк на текущей странице. KK-перевод обязателен;
- после нажатия видны все строки текущей страницы, пагинация и кнопка «Свернуть»;
- **в свёрнутом виде пагинация скрыта**;
- если строк 3 или меньше — ни кнопки, ни изменений: таблица выглядит как сейчас;
- состояние «развёрнуто» хранится только в памяти компонента: при уходе на другой раздел и возврате таблица снова свёрнута. Сервер, лимиты, запросы и пагинацию на сервере не менять;
- переход по страницам пагинации (Назад/Далее) таблицу не сворачивает;
- поиск и фильтр, которые меняют набор строк, тоже не сворачивают и не разворачивают таблицу. Кнопка показывает новое N;
- доступность: у кнопки `aria-expanded` и `aria-controls` на `tbody`/таблицу, видимый фокус.

Где менять:
- общий компонент `admin/src/components/DataTable.tsx`. Его используют `BusinessesPage`, `AgentsPage`, `ContentPage` (2 таблицы), `AuditPage`, `OperationsPage` (2 таблицы). Поведение должно появиться **во всех этих таблицах сразу**, без правок на каждой странице, если без этого можно обойтись;
- отдельная «ручная» таблица карт пользователя в `admin/src/pages/OperationsPage.tsx` (около строки 535, `user.cards.items.map`). Сделай ей то же поведение через общий маленький хук или компонент, без копипаста логики. У неё есть своя пагинация (Назад/Далее), см. уточнение куратора выше: поведение как у DataTable.

Выпадающие списки (`<select>`) и прочие не-табличные списки не трогать.
