## Авторизованный сценарий и границы

При доступной штатной сессии обеих ролей проверить реальные формы и read-only
действия: 7 строк/«Показать ещё», select-отступы, форму бизнеса, checkbox-режимы,
параметры фото, выбранный favicon, ошибка неверной даты/«Назад» и многолетний период.
Для статуса проверить понятность конфликта; не сохранять заведомо конфликтные/тестовые
пороги в реальном Keremet ради доказательства. Смена L1 на [0,300000) при старых
соседях всё ещё корректно запрещена — соседние границы не менять автоматически.

Настоящее сохранение баннера/акции/статуса и проверку изменения в приложении
выполнять только в заранее согласованной тестовой области с известной процедурой
возврата, не портить production-контент и не делать рассылок реальным клиентам.
Если такой области/штатного входа/Android нет — явно оставить соответствующие
сценарии открытыми. Mock/локальный API и InMemoryMediaStorage не являются live FTPS
или проверкой установленного 1.0.26. Если секрет может дать только владелец,
использовать защищённый request_secret, не просить пароль/токен в чате.
