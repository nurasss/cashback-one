# Новый курс: своё приложение для каждого клиента — 2026-11-04

Документ куратора. Решения владельца, путь клиента и сисадмина, разбивка на задачи. Код по нему пишут исполнители по отдельным промптам.

## 1. Решения владельца (2026-11-04)

1. Для каждого клиента (магазина или сети) отдельный APK: своё название, иконка, пакет. Все приложения работают с общим сервером `api.cashback-qr.poscenter.kz`.
2. QR в приложении статичный, внутри номер карты (`card.barcode`). Динамический QR `C1…` больше не развиваем, серверный код не удаляем.
3. Списание баллов подтверждается кодом. Кассир запрашивает код на кассе, покупателю приходит push-уведомление в приложение, покупатель называет код, кассир вводит его в Cash, Cash сверяет код с сервером.
4. Код: 4 цифры, действует 5 минут, не больше 5 неверных попыток.
5. Нет приложения или не принимаются уведомления — списание без кода не проводится. Кассир отказывает и предлагает скачать приложение.
6. Аккаунты бизнеса в кабинете создаёт суперадмин.
7. Ключ агента: показывается один раз при выдаче, дальше только «Перевыпустить ключ» (вариант Б). Хранить ключи в открытом или расшифровываемом виде не будем.
8. Установщик агента сам спрашивает ключ, ключ на компьютере хранится защищённо, не открытым текстом.
9. В установщике агента на шаге логина и пароля 1С есть кнопка «Проверить подключение».
10. Баннеры, акции и тексты магазина (название, адрес, ссылка на карту) не зашиты в приложение. Их правят в кабинете, приложение загружает и кеширует.

## 3. Путь клиента (магазин)

1. **Договорённость.** Магазин хочет программу лояльности. Нужно: POSCENTER Cash, POSCENTER ONE, компьютер с ONE, который работает в часы магазина, интернет.
2. **Данные для приложения.** Магазин передаёт: название приложения, логотип и иконку, фирменные цвета, название и адрес магазина (магазинов), ссылку на 2ГИС, тексты и картинки акций.
3. **Доступ в кабинет.** Суперадмин создаёт бизнес. Менеджер магазина получает логин, пароль и ссылку на `/admin/login` (показываются один раз).
4. **Подключение учёта.** Сисадмин ставит агента на компьютер с ONE. Через несколько минут в кабинете появляются карты и операции.
5. **Касса.** В Cash включают подтверждение списания по коду (доработка разработчиков Cash, раздел 6).
6. **Приложение у покупателей.** Магазин раздаёт ссылку на свой APK (QR-код на кассе, листовки). Покупатель ставит приложение, входит по номеру телефона через WhatsApp, видит свою карту, баланс, историю, акции.
7. **Покупка с начислением.** Покупатель показывает QR из приложения или пластиковую карту. Кассир сканирует, как обычную карту.
8. **Покупка со списанием.** Кассир сканирует QR, вводит сумму, нажимает «Запросить код». Покупателю приходит уведомление с кодом, он называет код. Кассир вводит его, Cash проводит списание. Нет приложения — списание не проводится.
9. **Баланс.** Начисления и списания попадают в ONE при закрытии смены, затем агент передаёт их в облако. В приложении баланс обновляется не сразу.
10. **Работа в кабинете.** Менеджер смотрит карты и операции, меняет баннеры, акции и тексты, отправляет уведомления. Изменения видны в приложении без нового APK.

## 5. Задачи и порядок

| № | Задача | Исполнитель | Зависит от |
|---|---|---|---|
| A | **Облако: push-уведомления.** Регистрация токена устройства (`POST /me/push-token`), отправка через Firebase (FCM HTTP v1), учёт пакета приложения. | Gemini | Проект Firebase (владелец) |
| B | **Облако: код списания через push.** 4 цифры, доставка уведомлением и записью в «Уведомления» приложения, отказ `CUSTOMER_NO_APP`, если нет активного push-токена. WhatsApp для списания отключить. | Gemini | A |
| C | **Приложение: уведомления.** `expo-notifications`, Firebase для Android, запрос разрешения, отправка токена, показ кода (уведомление + экран). Без `expo prebuild`, правки `android/` вручную. | Исполнитель приложения | A |
| D | **Агент: посредник списания в POS-сервисе.** `/v1/redemptions` и `/v1/redemptions/{id}/verify` к облаку, как `/v1/qr/resolve`. | Gemini | B |
| E | **Агент: установщик.** Ввод ключа агента, защищённое хранение (Windows DPAPI, доступ только службе), кнопка «Проверить подключение» к 1С только на чтение. Агент 0.3.0. | Gemini | — |
| F | **Код для Cash.** Окончательный `docs/integrations/cash_redeem_code.bsl` по фактическим адресам и кодам ошибок из B и D. | Gemini, проверка куратора | B, D |
| G | **Кабинет и облако: контент бизнеса.** Тексты магазина (название, адрес, ссылка на карту), баннеры, оформление; API для приложения. | Gemini | — |
| H | **Приложение: контент с сервера и кеш.** Убрать зашитые баннеры и текст магазина, грузить из G, кешировать. | Исполнитель приложения | G |
| I | **Приложение под клиента.** Файл настроек клиента (пакет, название, иконка, цвета, ID бизнеса), сборка APK по нему; приложение показывает только карты своего бизнеса. | Исполнитель приложения | G |
| J | **Ключ агента вариант Б.** Сверить кабинет: ключ показан один раз, кнопка перевыпуска понятна, предупреждение о старом ключе. | Gemini | — |

Что можно делать сразу и параллельно: A, E, G, J. Затем B и C, потом D и F, потом H и I.

Нужно от владельца:
- проект Firebase (или согласие, чтобы исполнитель создал по инструкции) и файл сервисного аккаунта на VPS — файл никому не пересылать в чат;
- решение по подписи: один ключ подписи на все APK клиентов или отдельный для каждого (рекомендация — отдельный, при утечке пострадает один клиент).

## 5а. Изменение 2026-11-04: касса обращается в облако напрямую

Разработчик Cash сообщил: агент стоит на компьютере оператора, на кассе его нет. Решение: Cash вызывает облако напрямую (`/pos/redemptions`, заголовок `X-Pos-Key`) отдельным **ключом кассы**, выдаваемым в кабинете. Ключ агента на кассу не кладём: он позволяет загружать балансы. Задача D отменена, задачи B и F объединены: промпт `docs/PROMPT_BACKEND_POS_REDEEM_PUSH_2026-11-04.md`, код для Cash `docs/integrations/cash_redeem_code.bsl`. В пути сисадмина (раздел 4) шаги 9–10: вместо POS-сервиса агента — «Выдать ключ кассы в кабинете» и «Ввести адрес облака и ключ кассы в настройки Cash».

## 6. Код для Cash: черновик (устарел, см. 5а)

Черновик в 1С выдан владельцу в чате 2026-11-04 (окно ввода кода, проверка через агента). Его адреса и коды ошибок — предварительные. Фактические: облако `/agent/redemptions` и `/agent/redemptions/{id}/verify`; ошибки `INVALID_CODE` (неверный код, можно повторить), `REDEMPTION_EXPIRED`, `REDEMPTION_MAX_ATTEMPTS_EXCEEDED`, `REDEMPTION_NOT_ACTIVE`, `CARD_NOT_FOUND`, `CARD_BLOCKED`, новая `CUSTOMER_NO_APP`. Окончательный файл — задача F, после B и D. Разработчикам Cash отдавать окончательный файл, не черновик.

## 7. Что это значит для 1.0.11-test

Статичный QR соответствует новому курсу. Текст магазина и 2ГИС, зашитые в приложение, допустимы только для пилота и уходят в задаче H. Промпт 2ГИС и сборку 1.0.11-test можно довести, если пилот нужен до готовности H.

## 5б. Решения 2026-11-05: задача I

- **Ключ подписи — один для всех клиентов** (решение владельца, «так меньше запары»): текущий `release.keystore`. У каждого клиента свой пакет (`kz.cashbackone.<slug>`), поэтому приложения разных клиентов ставятся рядом на одном телефоне.
- Задача I делится на две части. **I-backend** (`docs/PROMPT_BACKEND_PER_CLIENT_APP_2026-11-05.md`): у бизнеса поле `android_app_id`, push по коду списания уходит только в приложение этого бизнеса и в общее, необязательный `business_id` у `/me/*`. **I-app** (`docs/PROMPT_APP_PER_CLIENT_2026-11-05.md`): `mobile/clients/<slug>/`, flavors в Gradle, `build-client.sh`.
- Для каждого нового клиента в консоли Firebase нужно добавить Android-приложение с его пакетом и скачать новый `google-services.json`.
- **«КеремЕт» — новый клиент** (решение владельца 2026-11-05): своя ONE, агент на его компьютере с ключом бизнеса `keremet`. Бизнес `test` (1711 карт тестовой ONE) остаётся тестовым. Нужен агент 0.3.0: `docs/PROMPT_AGENT_EXE_0_3_0_2026-11-05.md`.
