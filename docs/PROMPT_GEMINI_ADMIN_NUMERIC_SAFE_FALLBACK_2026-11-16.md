# Gemini Mac: узкий защитный фикс fallback числовой вставки

Круг 2 исправил обычную вставку и проверил каретку в настоящем Chrome.
Не переделывать успешный путь, формы, подсказки, фавикон и E2E/backend заново.
Сфера: NumericInput и его регрессионные тесты, затем актуальный dist/отчёт.

## Два соседних небезопасных пути

1. Если selectionStart/End недоступны и document.execCommand отсутствует или
   insertText возвращает false, выполняется нижний setter.call(input, normalized).
   Это опять заменяет ВСЁ значение форматированной вставкой без учёта каретки.
   Куратор подтвердил на реальном экспортированном onPaste с DOM-двойником:
   value=100, clipboard='90 000', selectionStart/End=null, execCommand отсутствует
   → preventDefault=true, value=90000. При вставке в конце ожидалось 10090000.
   Комментарий «non-browser fallback» не ограничивает ветку только jsdom:
   условие также выполняется в браузере при недоступном/отказавшем API.
2. При invalidCombined код вызывает execCommand('undo'), но не проверяет
   успех/возвращённое значение и не гарантирует восстановление prevValue.
   Если undo не сработал, в DOM может остаться пустое/испорченное значение.
   Это вывод по коду, сценарий отказа undo в браузере куратором не воспроизводился.

## Минимальное требуемое изменение

Если корректная вставка по текущей позиции технически недоступна, не подставлять
нормализованный текст вместо всего поля. Безопасно сохранить исходное значение;
для форматированной вставки дать понятный способ ввести число без форматирования,
если поддержать позиционную вставку в таком браузере невозможно.
Обычные цифры с native paste должны продолжать работать как в круге 2.
Не обходить проблему select-all при фокусе и не снимать строгую нормализацию.

После неудачного insert/undo гарантировать согласованность DOM, controlled state
и отправляемого payload с исходным значением; никакой тихой подмены числа.
Не откатывать через undo несвязанные предыдущие действия пользователя.
Сохранить cursor/selection насколько API позволяет, не обещать неизвестную позицию.

Тесты текущего компонента: selectionStart/End=null; execCommand отсутствует,
insertText=false, insertText=true + invalidCombined + undo=false; при ошибочном
пути нет замены 100 на 90000/пустоту и нет изменённого POST/PATCH payload.
Тесты должны давать настоящий набор методов DOM-двойника (включая listeners),
либо использовать jsdom-элемент, а не падать из-за неполной фикстуры.
Существующая Chrome-матрица каретки и 301 тест сохраняются.
