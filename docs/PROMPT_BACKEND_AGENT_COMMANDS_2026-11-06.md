## Что сделать

### 1. Новый тип команды

- Миграция `0017`: `command_type IN ('full_resync', 'sync_now')`; уникальный индекс «одна активная (`pending`/`running`) команда на агента» — **для каждого типа отдельно**. Вниз — обратно (если есть строки `sync_now` — удалить их в `downgrade`, это служебные записи).
- `POST /admin/agents/{id}/sync-now` (202) — по образцу `full-resync`: те же права (сейчас `require_superadmin`), аудит `agent_sync_now_requested`, если такая команда уже активна — вернуть её (как сейчас у `full_resync`).

### 2. Протокол для агента (новые маршруты, старые агенты их не вызывают)

- `POST /agent/commands/claim` (ключ агента, как `/agent/heartbeat`): вернуть команды этого агента со статусом `pending`, перевести их в `running` (`claimed_at`). Ответ `{"commands": [{"id": "<uuid>", "type": "sync_now" | "full_resync"}]}`. Команды старше 24 часов в `pending` — пометить `failed` с `error="expired"` и не отдавать. `running` дольше 30 минут — пометить `failed`, `error="timeout"`.
- `POST /agent/commands/{id}/complete`: тело `{"status": "completed" | "failed", "error": str | null}` (`error` до 512 символов, без ПДн). Только команда этого агента и только из `running`; иначе 404/409 без раскрытия чужих команд. `completed_at` — время сервера.
- `/agent/heartbeat` **не менять** (ответ старым агентам побайтно прежний).
- Лимит частоты для `claim` — как у heartbeat (если он есть).

### 3. Кабинет

На странице агента (`AgentsPage.tsx`, деталь агента):
- кнопки **«Синхронизировать сейчас»** (KK **«Қазір синхрондау»**) и прежняя «Полная синхронизация» с пояснением: «Агент отправит все карты и операции заново. Дубли не появятся.» / KK «Агент барлық карталар мен операцияларды қайта жібереді. Қайталанулар болмайды.»;
- последняя команда каждого типа: статус («ожидает агента», «выполняется», «выполнено», «ошибка: …», «истекла»), время;
- пока агент старой версии: подсказка «Команды выполняет агент версии 0.4.0 и новее», если `agents.version` < 0.4.0.
