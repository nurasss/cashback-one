# Диагностика завершённых чтений ONE

Формат исходников обновлён 2026-10-23. Это не подтверждение обновления установленной Windows-службы: изменения должны попасть в отдельную следующую сборку EXE 0.2.1 и пройти приёмку на Windows. Версии/установщик этой задачей не меняются.

## INFO `ONE read completed`

Примеры с **синтетическими** числами:

```text
ONE read completed: type=cards_snapshot, records_read=5, changes_to_send=3, skipped_invalid_barcode=2 (empty=1, non_digits=1, too_short=0, too_long=0), duration=0.123s
ONE read completed: type=transactions_window, records_read=5, changes_to_send=3, skipped_invalid_barcode=2 (empty=0, non_digits=0, too_short=1, too_long=1), duration=0.456s
```

- `type`: полное чтение среза карт или чтение окна операций.
- `records_read`: все строки основного запроса ONE, включая записи с неправильным номером. Строки отдельного запроса начальных остатков сюда не входят.
- `changes_to_send`: найденные кандидаты для отправки, **не доказательство ACK облака или завершения всего цикла синхронизации**. Неизменённые карты и уже известные операции могут дать 0 при непустом чтении.
- `skipped_invalid_barcode`: число пропущенных строк из-за номера, сумма четырёх причин ниже, **только за это чтение**.
- `empty`: пустой номер после существующей обработки строки; `non_digits`: нецифровые символы; `too_short`: меньше 4 цифр; `too_long`: больше 13 цифр. Причины взаимоисключающие, определяются `_validate_card_barcode`; правило номера карты — **4–13 цифр** (сужено с прежних 6–15 2026-10-23; счётчики `too_short`/`too_long` отсчитываются от новых границ 4 и 13).
- `duration`: длительность чтения/обработки, секунды с тремя знаками после точки.

Для операций используются дельты `tx_skipped_*`, для карт — `cards_skipped_*`. Дельта берётся между началом и концом рабочего чтения. Накопленные `source.counters`, используемые dry-run, не сбрасываются и сохраняют прежнее значение за жизнь объекта.

Листание уже прочитанного буфера не выполняет новый COM-запрос и **не печатает повторную строку завершения**. При новом чтении счётчик начинается от дельты, а не от накопленного значения: два чтения с двумя плохими номерами дают две строки с `skipped_invalid_barcode=2`, а не 2 и 4. Пустое окно или окно только с пропущенными записями тоже получает строку завершения. При исключении строка об успешном завершении не печатается.

В сообщении только фиксированные названия и агрегатные числа — **нет** номеров карт, телефонов, имён, ссылок/UUID, SQL, конфига или секретов. Само число пропусков не является поводом менять облачный баланс или правило номера карты.

## Некорректная дата движения

Период движения ONE должен быть `datetime`, включая datetime-совместимое представление pywin32. Если поле отсутствует, равно `None` или имеет другой тип, окно отклоняется с `SourceProtocolError` и безопасным фиксированным текстом. Дата не подставляется и движение не пропускается молча; успешного завершения/выдачи нового курсора нет. Валидная дата обрабатывается прежним преобразованием локального времени ONE в UTC.

Для эксплуатации используйте завершённые чтения, heartbeat и `last_error` вместе. Старый `last_sync_at` при пустой дельте сам по себе не доказывает поломку. Исторические строки старой службы без новых полей остаются свидетельством её прежних чтений, а не текущей версии.
