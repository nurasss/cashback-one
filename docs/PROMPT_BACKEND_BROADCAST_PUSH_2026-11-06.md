## Решение владельца

При создании уведомления в кабинете отправлять push на телефоны.

## Что сделать

### 1. Кому отправлять (только активные устройства, `disabled_at IS NULL`)

- **Уведомление бизнеса B** (бизнес `active`):
  - все устройства с `app_id == B.android_app_id` (если задан) — с картой B или без;
  - устройства общего приложения (`app_id == push_shared_app_id`) только тех покупателей, у кого есть видимая карта B (`UserCard.hidden_at IS NULL`).
- **Уведомление «Все бизнесы»** (`business_id IS NULL`): все активные устройства всех приложений.
- Неактивный бизнес — push не отправлять.
- Каждое устройство — не больше одного сообщения на рассылку.

### 2. Отправка

- Заголовок и текст push = заголовок и текст уведомления. `data`: `{"type": "broadcast", "notification_id": "<id>"}`.
- Через существующий отправитель (`PushSender`), с тем же правилом: недействительный токен → `disabled_at`, временная ошибка — устройство остаётся. Маскирование кодов не затрагивать.
- Сначала сохранить уведомление (`commit`), потом отправлять. **Ошибка push не отменяет уведомление** и не даёт 500.
- Синхронно, с ограничением параллельности (например, 10) и общим тайм-аутом; устройств сейчас единицы. Если считаешь, что нужна фоновая задача, опиши почему, но не делай без решения куратора.
- `PUSH_PROVIDER_MODE=disabled` — push не отправлять, в ответе это видно.

### 3. API и кабинет

- В запрос создания уведомления (`NotificationCreateRequest`) — необязательное поле `send_push: bool = true`. Права прежние: менеджер — только своему бизнесу.
- В ответ создания — итог: `push: {"status": "sent" | "disabled" | "skipped" | "failed", "devices": N, "delivered": M}` (без токенов и телефонов). Миграция не нужна; если без неё не обойтись — СТОП.
- Кабинет (`admin/src/pages/ContentPage.tsx`, форма уведомления): галочка **«Отправить push на телефоны»** / KK **«Телефондарға push жіберу»**, по умолчанию включена. После создания — сообщение: «Push отправлен на {M} из {N} устройств» / «Push выключен на сервере» / «Push не отправлен: нет устройств» / «Push не отправлен: ошибка». RU/KK в `admin/src/i18n/admin.ts`.
- Журнал (`audit_log`): к событию `notification_created` добавить число устройств и доставок (без идентификаторов устройств).

## Тесты

Backend (fake-отправитель):
- бизнес B с `android_app_id`: устройство приложения B без карты — получает; общее приложение с картой B — получает; общее приложение без карты B — нет; приложение другого бизнеса C — нет;
- бизнес без `android_app_id`: только общее приложение с картой;
- «Все бизнесы»: все активные устройства; отключённые (`disabled_at`) — нет;
- `send_push=false` — не отправляется; режим `disabled` — `status: disabled`, уведомление создано;
- ошибка отправителя — уведомление создано, `status: failed`, ответ 201;
- недействительный токен — устройство помечено `disabled_at`;
- менеджер не может отправить в чужой бизнес.
