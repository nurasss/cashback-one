## 2. Существующее окно обновления

Факты из исходников: `appUpdate.ts` читает `https://cashback-qr.poscenter.kz/app/version.json`; принимает `{latest_version, latest_version_code, min_version_code, download_url}`; URL разрешён только вида `/app/cashback-one-X.Y.Z.apk`. `UpdateNotice` проверяет при запуске Android и при возвращении в foreground не чаще раза за 6 часов, имеет «Обновить»/«Позже» и обязательный режим. Нельзя считать, что клиент Keremet сейчас получает свой APK: текущая реализация общая.

- Сохранить поведение окна и старый формат manifest. «Обновить» открывает HTTPS-ссылку в браузере, приложение само не устанавливает APK. Сбой сети/JSON не блокирует работу. Обязательный режим не включать без отдельного поручения.
- Для новых сборок добавить manifest, выбранный по текущему клиенту: Cashback One продолжает читать общий `/app/version.json`, Keremet — отдельный `/app/keremet-version.json`. Новым клиентам путь задаётся в клиентском конфиге без копирования логики.
- Проверять URL против **своего** имени APK (`apk_name`) и доверенного origin/каталога. Cashback One не должен предлагать Keremet APK и наоборот. Не заменять строгую проверку на произвольные URL; учесть поле apk_name у общего клиента. При ошибке клиентского manifest не переходить на manifest другого клиента.
- Старые уже установленные APK изменить задним числом нельзя. Их общий `version.json` должен сохранить совместимые поля и ссылку на общий Cashback One APK, принимаемую старым парсером. **Не направлять общий manifest на Keremet.** Старые клиентские APK с общей проверкой смогут читать отдельный manifest лишь после установки исправленной версии: явно описать переход и ограничение.
- Сохранить проверку versionCode, необязательное/обязательное обновление и исключение demo/web; проверить, откуда versionCode приходит в нативной сборке flavor. Не объявлять установленный APK проверенным только по мокам Constants.
- Окно обновления должно выглядеть корректно в светлой/тёмной теме, RU/KK. В настройках рядом с версией добавить «Проверить обновления»: ручная проверка даёт результат «Установлена актуальная версия», доступное обновление либо понятную ошибку сети; не ограничивать её шестичасовым интервалом автоматической проверки. Не показывать ложное «актуальная версия» при ошибке запроса.
- Подготовить в отчёте схему публикации обоих manifest и перехода старых версий. Не публиковать manifest сейчас и не указывать несуществующий будущий APK как доступный. Сначала сборка → проверка файла → публикация отдельного APK → обратное скачивание/хеш → только потом обновление соответствующего manifest по отдельному заданию. min_version_code не повышать самовольно.

Куратор пробовал прочитать публичный version.json 2026-11-09, запрос остановился на локальном `CERTIFICATE_VERIFY_FAILED`; актуальное содержимое в эту сессию не подтверждено. Не отключать проверку TLS и не принимать старые записи о версии как текущую проверку сервера.
