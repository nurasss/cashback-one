## Задача

### 1. Магазины бизнеса

Новая таблица `business_stores`, миграция `0013_business_app_content` (down_revision `0012_push_devices`), с рабочим downgrade:

- `business_id` (каскадное удаление), `title_ru`, `title_kk` (название, например «Супермаркет «КеремЕт», ТЦ «In Plaza»»), `address_ru`, `address_kk`, `map_url` (необязательно), `sort_order`, `is_active`, `created_at`, `updated_at`.
- `map_url` — только `https://`, до 1024 символов. Белый список хостов не вводить, но запретить `javascript:`, `data:`, адреса без хоста.
- Длины полей разумные (название до 160, адрес до 255). Пустые строки не сохранять, обрезать пробелы.

### 2. Тексты приложения

Поле `app_texts` в `businesses` (JSON) или отдельная таблица — выбери и объясни. Набор ключей **закрытый**, заданный в коде:

- `home_store_note_lead` — начало фразы на главной перед адресом, RU и KK (сейчас «Вы можете потратить эти баллы в …, по адресу: »);
- `balance_delay_note` — текст о задержке баланса на экране «Мой статус», RU и KK.

Для каждого ключа значение `{ "ru": str | null, "kk": str | null }`, до 500 символов. Пусто — приложение покажет свой встроенный текст. Неизвестные ключи — ошибка 422.

### 3. API кабинета

- `GET/POST /admin/businesses/{id}/stores`, `PATCH/DELETE /admin/businesses/{id}/stores/{store_id}`;
- `GET/PUT /admin/businesses/{id}/app-texts`.

Права как у акций: суперадмин — любой бизнес, менеджер — только свой, чужой бизнес — 404 без раскрытия существования. Каждое изменение — запись в `audit_log`, как у акций. CORS: `PUT` и `PATCH` уже разрешены? Проверь (недавно не хватало `DELETE`) и напиши в отчёте.

### 4. API приложения

`GET /me/app-content?business_id=<uuid>`:

- отдаёт активные магазины по `sort_order` и тексты бизнеса; только если у покупателя есть карта этого бизнеса, иначе 404;
- заголовки `ETag` и `Cache-Control: private, max-age=300`; на `If-None-Match` с тем же значением — 304. Приложение будет кешировать ответ и показывать последний сохранённый без интернета;
- поле `updated_at` — самое позднее изменение магазинов и текстов.

Опиши формат в `docs/CUSTOMER_API.md`.

### 5. Кабинет

Раздел «Приложение» на странице бизнеса для суперадмина и на `ContentPage` для менеджера (или отдельная вкладка — выбери по устройству кабинета, объясни):

- список магазинов с добавлением, правкой, удалением (с подтверждением), порядком и включением;
- поля текстов RU и KK с подсказкой, где текст показывается в приложении, и встроенным текстом как placeholder;
- проверка ссылки на карту в форме, понятные ошибки;
- все подписи RU и KK в `admin/src/i18n/admin.ts`, стиль и компоненты как у соседних форм, работает на телефоне (боковое меню уже есть).

Начальные данные пилота («КеремЕт», адрес, ссылку 2ГИС) **не вносить миграцией** — владелец внесёт через кабинет.
