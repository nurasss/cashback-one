## Общие правила FTPS

Учётные данные — в `.env.hosting.local`: `HOSTING_FTPS_HOST`, `HOSTING_FTPS_USER`, `HOSTING_FTPS_PASSWORD`, `HOSTING_SITE_DIR`. Значения не печатать.

Свой временный Python-скрипт вне репозитория. `scripts/upload_admin.py` и `scripts/upload_apk.py` не использовать.

- `ftplib.FTP_TLS`, проверка сертификата включена, `context.maximum_version = ssl.TLSVersion.TLSv1_2`, запуск с `SSL_CERT_FILE=/etc/ssl/cert.pem`, `prot_p()`, `TYPE I`;
- каждый файл: временное имя → скачать обратно → сверить SHA-256 → `rename`;
- **сервер отвечает 200 на несуществующие пути**: наличие файла проверяй списком FTP, а публикацию — по содержимому и SHA-256, не по коду ответа.

## Часть 1. Временный `version.json`

Цель: на телефоне с 1.0.10 появляется необязательное окно. Его увидят только установившие 1.0.10; прежние версии файл не читают.

2. Создай файл вне репозитория и выложи как `app/version.json`, без BOM, UTF-8:

   ```json
   {
     "latest_version": "1.0.11",
     "latest_version_code": 12,
     "min_version_code": 1,
     "download_url": "https://cashback-qr.poscenter.kz/app/cashback-one-1.0.10.apk"
   }
   ```

3. Проверь: `curl -sS https://cashback-qr.poscenter.kz/app/version.json` разбирается как JSON, поля равны заданным, SHA-256 совпадает с локальным. Покажи `Content-Type`. Убедись повтором через `curl -H 'Cache-Control: no-cache'`, что ответ тот же. Прочие файлы `app/` и SHA-256 главной не изменились.
4. Стоп. Напиши владельцу дословно: «Файл выложен. Полностью закройте приложение 1.0.10 и откройте снова. Должно появиться окно “Доступна новая версия” с кнопками “Обновить” и “Позже”. Нажмите “Позже”: окно закроется и в этот запуск не вернётся. Закройте и откройте снова, нажмите “Обновить”: должна открыться загрузка APK. Обновлять не обязательно. Затем напишите “Окно проверено” или опишите, что пошло не так.»

Если владелец сообщил о проблеме — ничего не меняй, принеси его слова куратору. Временный файл оставь, пока куратор не решит иначе: окно необязательное, вреда пользователям нет.
