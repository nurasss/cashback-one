# Claude: управляемая заставка приложения — после контракта Gemini

Это следующая задача после текущей сборки APK Keremet 1.0.17. Не менять mobile во время сборки и не добавлять новую функцию в уже собираемый артефакт. Прочитать AGENTS.md, CLAUDE.md, `docs/PROMPT_ADMIN_TITLE_APP_SPLASH_2026-11-09.md` и принятый куратором `reports/ADMIN_TITLE_APP_SPLASH_2026-11-09.md`. Если принятого контракта ещё нет — зависимую реализацию не начинать, контракт не придумывать.

**Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть.** Только mobile и отчёт, backend/admin не менять. Без APK, commit/push и публикации на этапе реализации.

Нужно: картинка либо короткое беззвучное видео, загруженные владельцем магазина в кабинете, показываются при холодном запуске после системной native splash. Показ максимум 5 секунд, доступная кнопка «Пропустить» сразу. Не показывать заново при каждом переходе между вкладками/возврате из background и после открытия внешней ссылки. Не блокировать целевой экран push/deep link: после пропуска/завершения сохранённый маршрут должен открыться правильно. Ошибка медиа/плеера/сети сразу ведёт к нормальному запуску.

Native заставка остаётся встроенной в APK. Удалённые настройки не могут заменить самый первый кадр ОС. Выключено/неизвестно/первый запуск без сети → обычный запуск с локальным брендом, без долгого ожидания сети. Новые настройки применяются после получения/кеширования; гарантировать свежую заставку при первом offline-запуске нельзя. Кеш по клиенту и версии настройки, без путаницы Keremet/Cashback One, безопасная замена и ограничение размера; не очищать пользовательские токены ради кеша.

Только HTTPS медиа из принятого backend-контракта. Уважать уменьшение движения: видео можно заменить статичным первым кадром/локальным брендом; звук никогда не включать. Картинку не искажать/не инвертировать в dark, безопасные отступы и выход из заставки доступны на 360/390. Не запускать системное окно обновления поверх заставки; согласовать порядок с проверкой обновления, обязательный режим сохранить.

Текущий Expo SDK55: для видео использовать поддерживаемый expo-video после Context7 resolve/query; нужную зависимость и lockfile менять согласованно, без expo prebuild и скрытых native-изменений. Зависимость потребует новой сборки после приёмки исходников. Системные панели/статусбар, сессия и ThemeProvider не должны ломаться.

Тесты: cold start/foreground, cached/offline/timeout, enable/disable/change media, два клиента, skip/end/error и максимальная длительность, push/deep link, порядок UpdateDialog. baseline/итог npm test/typecheck/lint и diff --check, полные безопасные выводы. Снимки реальных экранов на изолированных данных; Android playback не считать проверенным браузером/моками.

Отчёт `reports/APP_MANAGED_SPLASH_2026-11-09.md`: контракт, реализация и кеш, проверки/ограничения/непроверенное. После приёмки отдельное задание на следующий APK; 1.0.17 не пересобирать и не заменять молча.
