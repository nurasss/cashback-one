Куратор принимает форму координат и форму публичного каталога за основу. До окончательной передачи Claude поправить следующие конкретные места контракта, затем можно реализовывать пункты 5–14 по исходному заданию без ожидания ещё одного общего согласования редакторов/таблиц:

1. Правильный endpoint — **GET /me/app-content**, router /me + /app-content. Сейчас /app/content в документе не существует. Менять название endpoint ради черновика не нужно.
2. API latitude/longitude должны быть **JSON numbers|null**, а не строками Decimal. Numeric в БД допустим, response schema должна сериализовать в float с корректным диапазоном и парностью. PATCH одного поля валидировать после слияния с существующей записью; очищать пару явным null по понятному контракту. Старые записи без координат сохраняются. Описать admin CRUD и scoped GET/мутации, не только мобильный пример.
3. Каталог AppContent.loyalty_tiers не содержит выбранного личного уровня. Зафиксировать **отдельный приватный ответ для конкретной карты** в существующем карточном API (аддитивное поле, не ломая legacy tier): known, reason, tier_id|null, program_version, calculated_at, coverage/freshness и оборот нужного окна. Публичный каталог/контент без карты не должны выдавать персональные покупки. Расчёт выполняет сервер по подтверждённой истории; mobile не пытается собрать разные периоды из одного spend_total.
4. Если для некоторых окон данные подтверждены, а для более приоритетного ещё неизвестны, нельзя выбрать нижний уровень как будто доказано, что верхний не подходит. Либо достаточная coverage для всех уровней, способных изменить выбор, либо known=false. Различить unconfirmed/no_match/stale, не подменять нулём. Один стабильный tie-break priority→level→id либо запрет дублирующихся приоритетов; правило зафиксировать.
5. Названия/описания/картинки/периоды/проценты в каталоге действительно редактируемы и приходят с version. Любое их изменение обновляет версию/ETag/updated_at, иначе кеш мобильного app-content не узнает об изменении. Прописать поведение старых APK/legacy loyalty_tiers и отсутствие автоматического изменения кассовых начислений. Примеры KK-названий Keremet не выдавать за утверждённые владельцем; пока брендовые названия можно оставить русскими, как в согласованном каталоге.
6. Источник оборота ещё не готов. Реализация редактора/каталога может идти сейчас, private status должен оставаться явно unconfirmed. Действующий расчёт реальных статусов и интеграцию с агентом не объявлять выполненными. Связать с docs/PROMPT_AGENT_PURCHASE_TURNOVER_2026-11-09.md, с учётом отдельных периодов 1..36 месяцев.
