## 1. Перехват ответа в E2E

В scripts/verify_admin_eleven_items_final_20261116.py фильтровать GET audit
по точному api_origin и pathname /admin/audit, допускаются query-параметры.

и Content-Type application/json. При несоответствии сохранить status, URL,
content-type и ограниченный безопасный body, затем СТОП. Не подменять JSON
пустым объектом и не исключать проверку событий при ошибке перехвата.

## 2. Ролевой запрос StatusesPage

В admin/src/pages/StatusesPage.tsx использовать существующий enabled-параметр
useBusinesses({ limit: 100, offset: 0 }, isSuperadmin).
Сам хук вызывать безусловно по правилам компонентов, отключается только query.
Менеджер получает свой businessId из сессии, не списка бизнесов. Суперадмин
сохраняет загрузку списка и выбор бизнеса. Не давать менеджеру новых прав API.

Адресный тест: manager открывает Статусы, его tiers/scale загружаются, запросов
GET /admin/businesses?… нет; superadmin этот список получает и выбор работает.
Не разрешать 403 в expected-errors ради маскировки дефекта и не отключать query
всех ролей. Сохранить прежний отрицательный тест доступа к чужому бизнесу.
