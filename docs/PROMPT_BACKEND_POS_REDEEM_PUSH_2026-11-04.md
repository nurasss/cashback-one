## Почему отдельный ключ кассы

Ключ агента позволяет загружать карты и операции в облако. Если положить его на кассу, утечка с кассы даст возможность подменить балансы в облаке. Ключ кассы может **только** запрашивать и проверять коды списания своего бизнеса.

### 2. API для кассы

Новый роутер `backend/app/api/pos.py` с префиксом `/pos`, авторизация заголовком `X-Pos-Key`. Ошибки: нет заголовка — 401 `POS_KEY_MISSING`; неизвестный ключ — 401 `POS_KEY_INVALID`; отозванный — 401 `POS_KEY_REVOKED`. Обновлять `last_used_at` не чаще раза в минуту.

**`POST /pos/redemptions`** — тело `{ "barcode": str, "amount": str | number }`:
- `barcode` — 4–13 цифр (`BARCODE_REGEX`), `amount` > 0 (Decimal, принимать строку `"150.5"`);
- карта ищется только в бизнесе ключа кассы: нет — 404 `CARD_NOT_FOUND`; заблокирована — 409 `CARD_BLOCKED`;
- покупатель — владелец карты через `UserCard` (не удалённый). Нет владельца или нет активного push-устройства (`has_active_device`) — **409 `CUSTOMER_NO_APP`**, код не создаётся;
- лимит как сейчас — 429 `RATE_LIMIT_EXCEEDED`;
- код **4 цифры** (`generate_sms_otp(4)`), прежние ожидающие коды карты — `superseded`, срок и попытки — прежние настройки;
- отправка через `send_to_user`: заголовок «Код для списания баллов», текст «Код {code} для списания {сумма} баллов в «{название бизнеса}». Назовите его кассиру, только если сейчас оплачиваете покупку.», `data` — `{"type": "redemption_code", "redemption_id": ...}`, **без кода в `data`**. Ноль доставленных — откат записи и 503 `PUSH_DELIVERY_FAILED`;
- ещё создать запись `Notification` для этого покупателя (`user_id`, `business_id`, тот же текст), чтобы код был виден в разделе уведомлений приложения, если push не показался. Учти: код попадает в базу открытым текстом в уведомлении — опиши это в отчёте и предложи, когда удалять (например, при подтверждении или истечении);
- ответ **201** `{ "redemption_id": uuid, "expires_at": datetime }`. Телефон покупателя в ответе не возвращать.

**`POST /pos/redemptions/{id}/verify`** — тело `{ "code": str }` из 4 цифр:
- запись только своего бизнеса, иначе 404 `REDEMPTION_NOT_FOUND`;
- ошибки и коды как в `verify_redemption`: 400 `INVALID_CODE`, 409 `REDEMPTION_EXPIRED`, 409 `REDEMPTION_MAX_ATTEMPTS_EXCEEDED`, 409 `REDEMPTION_NOT_ACTIVE`, 409 `REDEMPTION_ALREADY_CONFIRMED`;
- ответ 200 `{ "status": "confirmed", "barcode": str, "amount": "150.5000" }` — `amount` строкой, как сейчас в `RedemptionVerifyResponse`.

Формат ошибок — общий `{"error": {"code", "message"}}`.
