## Цель (как сформулировал владелец)

Сейчас в админке картинку для баннера, предложения или логотипа бизнеса можно указать **только ссылкой** (поле `image_url` / `logo_url`, только `https://`). Нужно:

1. Добавить в админку **загрузку картинки файлом**. Ссылка остаётся как альтернатива.
2. При загрузке картинка **сразу конвертируется в WebP**, чтобы занимать мало места.
3. Файлы хранятся **не на VPS, а на хостинге сайта** `https://cashback-qr.poscenter.kz/` (тот же хостинг, куда выкладывается сайт; FTPS). В базе хранится только итоговая ссылка, как и сейчас.

Охват по решению владельца:
- картинки промо-материалов (`kind = banner` и `offer`) в разделе «Контент» (`admin/src/pages/ContentPage.tsx`);
- **логотип бизнеса** (`logo_url`), там же, где он сейчас редактируется. Найди это место сам: `BusinessesPage.tsx` / `AdminMutations.tsx`.

**Мобильное приложение не меняется.** Android показывает WebP штатно, а приложение и так грузит картинку по `image_url`. Новый APK для этой задачи не нужен.

## Как сделать

### Backend

1. Зависимости: `Pillow` и `python-multipart` с точными версиями в `backend/requirements.txt`, `backend/requirements.lock` и `pyproject.toml`, как там принято. Убедись, что образ из `backend/Dockerfile` их соберёт (wheels для его базового образа). Docker сам не запускай, если не хватает места: смотри «Ограничения».
2. Настройки (`backend/app/core/config.py`), все необязательные:
   - `MEDIA_FTPS_HOST`, `MEDIA_FTPS_PORT` (по умолчанию 21), `MEDIA_FTPS_USER`, `MEDIA_FTPS_PASSWORD` (SecretStr);
   - `MEDIA_FTPS_ROOT_DIR` — путь до корня сайта на хостинге;
   - `MEDIA_PUBLIC_BASE_URL` (по умолчанию `https://cashback-qr.poscenter.kz/media`);
   - `MEDIA_MAX_UPLOAD_BYTES` (по умолчанию 10 МБ).

   Если FTPS не настроен, загрузка возвращает 503 с понятным кодом ошибки, а остальной backend работает как раньше. Добавь эти переменные в `deploy/vps/make-env.sh` и `.env.example`, **без значений**.
3. Хранилище: интерфейс `MediaStorage` (`put(path, bytes)`, `delete(path)`) и реализация через `ftplib.FTP_TLS`:
   - TLS с проверкой сертификата, `prot_p`, binary mode, таймауты;
   - вызов через `asyncio.to_thread`;
   - загрузка во временное имя → проверка размера → `rename`;
   - создание каталогов `media/promotions/` и `media/logos/` при отсутствии.

   Для тестов сделай фейковое хранилище в памяти и подставляй его через dependency override. **В тестах реального сетевого доступа нет.**
4. Эндпоинт `POST /admin/media/images` (multipart: `file`, `purpose` = `promotion` | `logo`):
   - доступ — `authenticate_admin`, любой вошедший администратор, включая `business_manager`. Права на сам объект по-прежнему проверяют существующие create/update при сохранении ссылки;
   - лимит размера **читается потоково**: не грузить в память больше `MEDIA_MAX_UPLOAD_BYTES + 1`, при превышении — 413;
   - проверка, что это действительно картинка (Pillow, а не расширение и не Content-Type). Принимать JPEG, PNG, WebP, GIF (берётся первый кадр). HEIC и всё остальное — 415 с понятным кодом;
   - защита от «бомб»: `Image.MAX_IMAGE_PIXELS` около 40 Мп, превышение — 413/415, не 500;
   - `ImageOps.exif_transpose`, затем сохранение **без EXIF/GPS/ICC-метаданных**. Прозрачность PNG сохраняется;
   - уменьшение без увеличения: промо — до 1600 px по длинной стороне, логотип — до 512 px. WebP `quality=80`, `method=6`. Если WebP получился больше исходника, всё равно WebP: единый формат;
   - имя файла: `media/<promotions|logos>/<uuid4hex>.webp`. Имя от пользователя нигде не используется;
   - ответ: `{ "url": "<MEDIA_PUBLIC_BASE_URL>/<promotions|logos>/<id>.webp", "width", "height", "bytes" }`;
   - запись в существующий audit log, если он есть для админ-действий: кто, purpose, итоговый размер. Без содержимого файла;
   - ошибка хостинга — 502 с безопасным текстом. Хост, логин, пароль, путь и трассировки в ответ и в логи не попадают.
5. Удаление старых файлов (экономия места). После **успешного** сохранения промо или бизнеса, у которого сменилась картинка, и после удаления промо — best-effort удалить старый файл. Условия:
   - старая ссылка начинается с `MEDIA_PUBLIC_BASE_URL`;
   - путь строго совпадает с `^(promotions|logos)/[0-9a-f]{32}\.webp$`;
   - на эту ссылку больше никто не ссылается в БД.

   Ошибка удаления не ломает основной запрос, только пишется в лог. Удаление чего-либо за пределами `media/promotions|logos/` невозможно **по построению кода**: проверь это тестом.
6. Загруженные, но так и не сохранённые файлы (форму закрыли) в этой задаче не чистим. Отметь это в отчёте как известное ограничение.
7. Схемы и валидатор ссылок не ослабляй: по-прежнему только HTTPS. Миграции БД не нужны. Если без миграции никак — СТОП.
