**Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть.** В прошлом логе несколько ошибок команд были пройдены без остановки; эту практику не повторять. Ожидаемое отсутствие совпадений rg отделять от ошибок соединения/SQL/COM. Самостоятельно не исправлять среду и не повторять неуспешные мутации.

## Сначала исправить неточности своего отчёта

- API по текущим backend/app/main.py и api/admin.py — `PATCH /admin/businesses/{id}` на API origin, не `/api/admin/...`. Проверить маршрутизацию по исходникам, не выполнять запрос с изменениями.
- План отката — через штатный API с предварительной защищённой копией исходного значения. Прямой UPDATE не выполнять и не назначать пользователю как обычную команду. Ничего в БД сейчас не менять.
- Подтверждено отсутствие оборота в текущей синхронизации. «В ONE нет готового показателя», полнота/смысл СуммаЧека и структура возвратов без реального исследования метаданных Keremet — гипотезы, не факты.

## Подготовить самодостаточное задание на Windows с ONE клиента Keremet

Mac не запускает COM, KONS2 подключён к тестовой int. Не подменять исследование реального клиента результатом тестовой копии. Пользователь передаст Windows-задание нужному исполнителю; не просить ключи и конфиг в чат.

Задание должно включать изолированный read-only скрипт/команды метаданных с явной папкой вывода вне ProgramData/state; без старых scratch/debug, Stage0, регистрации COM, изменения состояния агента, настройки, остановки/перезапуска службы. Подключение — через существующую безопасную процедуру, без секретов CLI/вывода. Если такой способ недоступен — остановиться и назвать prerequisite, не расшифровывать секреты для печати.

Цель: найти штатный показатель статуса или оборота покупок по карте за последние шесть календарных месяцев. Проверить реальные объекты/поля и связь с картой, суммы покупок/возвратов, дубли документа/строк, покупки без начислений. Сначала метаданные и ограниченные агрегаты с лимитом времени; не запускать полный скан боевой базы. Не создавать тестовые чеки/документы и не редактировать ONE.

Результат: какие источники действительно существуют, полнота, возвраты, бизнес-часовой пояс и границы rolling-окна, небольшой безопасный запрос и оценка нагрузки. Пересчёт должен учитывать выпадение старых покупок даже без новых операций. Если данных недостаточно — честный блокер, без приближённого оборота из бонусов.

Не реализовывать сбор/синхронизацию/миграции до приёмки исследования. Не включать loyalty_tiers и turnoverConfirmed, не менять начисления Cash. Не запускать команды на другом компьютере вслепую: в каждом блоке обозначить машину.
