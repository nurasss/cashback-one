## Особые ограничения

- Доступ к production только для ограниченных read-only проверок. SQL выполнять в `SET TRANSACTION READ ONLY`, с коротким `statement_timeout`; выводить агрегаты без карт, телефонов, имён и идентификаторов клиентов. Не создавать авторизационные сессии покупателей ради проверки.
- В прежней выкладке уже был `Permission denied` при чтении `/opt/cashback-one/secrets/firebase-service-account.json`. Не повторяй попытку, не обходи отказ через `sudo`, другой UID/контейнер, не меняй ACL. Этот незакрытый барьер явно перенеси в план; путь содержит секрет, его содержимое не нужно для диагностики расчёта статуса.
- Не печатай `.env`, вывод `docker inspect` с окружением, ключи, пароли, токены, signing keys и строки подключения. Не передавай секреты аргументами процессов. Разрешено вывести только имя и булево значение конкретного флага без остального окружения.
- Не меняй production env/compose, образы, контейнеры, миграции, настройки статусов, суммы, ONE, службу агента, SQLite/HMAC, маппинг, mobile/admin, APK/EXE, манифесты обновлений и GitHub Releases. Не отправляй `sync_now`/`full_resync`.
- Не зашивай пример шкалы или минимальный процент. Сервер использует настройки бизнеса; приложение показывает минимальный статус только по уже принятому правилу fallback.
- Применение серверного процента на кассе — отдельная нереализованная интеграция. Подготовка backend не подтверждает начисление 2% или другого процента в Cash.
- **Упало или неожиданно — СТОП и сырой вывод с сокрытием секретов/ПДн. Без самостоятельных исправлений, повторных запусков после ошибки и повторных мутаций.** Ожидаемые прежние блокеры опиши заранее, не воспроизводи их ради отчёта.
