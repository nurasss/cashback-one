# Gemini: замечания приёмки заставки и дат кабинета — 2026-11-09

Прочитать AGENTS.md и `reports/ADMIN_SPLASH_OWNER_REVIEW_2026-11-09.md`. Сохранить все принятые правки admin/backend и работу Claude. Без mobile, production, deploy, commit/push. APK 1.0.17 уже опубликован — его и manifest не трогать.

**Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть.** Не повторять прежнюю практику многократных перезапусков и изменения фикстур после ошибок без сообщения владельцу. Отчёт должен содержать падения и границы проверок.

1. **Свои медиа и серверные метаданные.** При загрузке splash сохранить проверяемую привязку asset к бизнесу и реальные метаданные (постоянное хранение, не in-memory). PUT не должен принимать чужой/неизвестный/несуществующий asset; размеры/тип/длительность/байты брать с сервера. Проверять также disabled config, чтобы произвольный URL нельзя было записать в обход enabled-проверки. Сохранить суперправа, атомарную замену и действующее медиа при ошибке. Тесты: upload бизнесом A → PUT бизнесом B с этим URL отклоняется; случайный UUID/не тот тип/поддельные метаданные; собственная замена и повторное сохранение. Не считать проверку префикса и UUID проверкой владельца. Выбрать минимальный устойчивый контракт, обновить миграцию/план без конфликтов следующего номера.

2. **Реально валидное видео.** Опциональный ffprobe с fail-open не подтверждает воспроизводимость файла. Подготовить ограниченную серверную проверку реального MP4/H.264; при отсутствии проверяющего инструмента, его ошибке или тайм-ауте отклонять видео понятной ошибкой, не принимать поверхностный разбор заголовков как полную проверку. При необходимости добавить зависимость в Dockerfile и план сборки образа, не ставить пакеты на VPS сейчас. Без shell/произвольных внешних ресурсов, с ограничением времени/размеров. Настоящий короткий беззвучный MP4 fixture плюс повреждённые/пустые/без mdat/truncated mvhd v1/слишком длинные файлы; не объявлять header-only make_mp4 валидным видео. Строго согласовать <=5 секунд между валидатором/формой/контрактом; случайное превышение 5.05 не выдавать за 5.0. Невалидные файлы дают 4xx, не struct.error/500. Проверить реальные треки/габариты и нормальную работу после загрузки.

3. **Окно дат.** На create «начать сейчас» (starts_at=null) + ends_at в прошлом должно отклоняться. На PATCH при изменении дат проверять итоговую запись после слияния, включая null-start. Не запрещать сохранение текста/картинки действующей/завершённой старой акции из-за неизменённых исторических дат. Убрать произвольный 5-минутный допуск прошлого: если нужна защита от секунд сетевой задержки у «Начать сейчас», передавать null или явно отличать это действие, а не разрешать прошлое для всех вводов. Тесты effective-now/вчера/равенство/строго позже, old unchanged dates, дата конца без даты начала, UTC+5 и переход суток. UI должен не только иметь type=datetime-local, но реально позволять открыть календарь на поддерживаемом desktop/mobile; показать снимок/проверку открытого выбора даты и заблокированного прошлого.

4. **Готовность к выкладке.** Выполнить миграции up/down на временном PostgreSQL с изолированным URL, не на production, и зафиксировать команды/результат. Подготовить точечное изменение reverse proxy: /admin/media/splash с лимитом, учитывающим multipart и 15 MiB файла, остальные пути не повышать. Никаких изменений VPS сейчас. Существующая настройка 12MB для /admin/media/images не покрывает новый endpoint.

После исправлений целевые backend/admin тесты, typecheck/lint/build и diff --check. Моки не равны интеграции. Обновить оба отчёта ADMIN_TITLE_APP_SPLASH и ADMIN_OWNER_CORRECTIONS с разделом приёмки, реальным стабильным контрактом для Claude, миграциями/зависимостями и непроверенным.
