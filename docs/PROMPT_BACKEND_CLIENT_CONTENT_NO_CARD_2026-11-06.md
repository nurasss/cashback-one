Сейчас приложение клиента (например Keremet Bonus, `business_id` KeremEt) показывает баннеры, акции, тексты и магазины, уведомления своего магазина **только если у покупателя есть карта этого магазина**. Без карты — пусто, а `/me/app-content` отвечает 404.

## Решение владельца

Кто скачал приложение магазина, тот видит информацию этого магазина **всегда**, с картой или без. Карта нужна только для баланса, статуса, истории и QR.

## Что сделать

Режим **с** параметром `business_id=B` (приложение клиента):
- `GET /me/promotions`, `GET /me/promotions/{id}`: баннеры и акции бизнеса `B` видны **без проверки карты**, плюс общие баннеры (`business_id IS NULL`, `kind='banner'`) как сейчас. Общие `offer` — по-прежнему нет. Окно активности (`is_active`, `starts_at`, `ends_at`) без изменений. Если бизнес `B` не существует или не `active` — только общие баннеры, `GET /me/promotions/{id}` для его акций — 404.
- `GET /me/notifications`, `POST /me/notifications/read`, `GET /me/badges`: рассылки бизнеса `B` (`user_id IS NULL`, `business_id = B`, `created_at >= user.created_at` — это правило оставить) видны без карты; личные уведомления покупателя (`user_id = он`) бизнеса `B` — как сейчас. Бейджи считать так же.

`GET /me/app-content?business_id=B` (тексты и магазины): **убрать требование карты** (`backend/app/api/customer_app.py`, функция `get_app_content`, шаг 1). Бизнес должен существовать и быть `active`, иначе 404, как сейчас. ETag/304 без изменений. Общее приложение запрашивает этот маршрут только для бизнеса своей карты, поэтому для него поведение по смыслу не меняется.

Режим **без** `business_id` (общее приложение и старые APK): `/me/promotions`, `/me/notifications`, `/me/badges` — ответ **побайтно прежний**.

Баланс, карты, история, QR, привязка, push и `/pos/*` — не менять. Обнови `docs/CUSTOMER_API.md`.

## Тесты

- покупатель с картой B: всё как раньше.
