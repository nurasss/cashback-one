## Задача

1. Свяжи уведомление с запросом кода: колонка `notifications.redemption_id` (nullable, FK на `redemption_codes.id`, `ON DELETE SET NULL`, индекс). Миграция `0015_notification_redemption` (down_revision `0014_pos_keys`), рабочий downgrade. Заполняй её в `request_pos_redemption`.
2. Как только запрос перестаёт быть ожидающим (`confirmed`, `expired`, `exhausted`, `superseded`), замени текст связанного уведомления нейтральным без кода, в той же транзакции, что смена статуса:
   - `confirmed`: «Списание {сумма} баллов в «{бизнес}» подтверждено на кассе.»
   - остальные: «Код для списания {сумма} баллов в «{бизнес}» больше не действует.»
   Заголовок оставить «Код для списания баллов».
3. Код, который истёк без обращения кассы, статус сам не меняет. Поэтому при выдаче уведомлений покупателю (`GET /me/notifications` и любой другой путь, который отдаёт `body` покупателю) у уведомления со связанным запросом, который не `pending` или у которого прошёл `expires_at`, отдавай нейтральный текст вместо сохранённого. Фоновую задачу не добавлять.
4. Push-уведомление на телефоне это не убирает — так и задумано, опиши в отчёте.
