## Теперь выполнить К1

Редактор всей шкалы: GET scale → существующие строки и версия → пользователь
меняет связанные границы → одна кнопка Сохранить шкалу → один PUT.
Все существующие строки обязательны. Границы и проценты отправлять строками,
null означает отсутствие верхнего предела. Опущенные необязательные поля
не менять; не подставлять пустые значения вместо не редактировавшихся.
Level/priority и создание/удаление не входят в этот запрос.
Не пересчитывать границы соседей и не предлагать тестовые числа как рабочую шкалу.
Дать пользователю явно увидеть итог всех уровней перед сохранением.

RU/KK: ошибки конкретных строк/пар при пересечении; max>min; отрицательные/дробные
деньги по контракту; конфликт версии с сохранением ввода и подтверждением загрузки
актуальных данных. Не делать автоматический overwrite. changed:false — штатный успех.

Поддержка старого backend: только 404/405 от GET scale означает отсутствие операции.
Прежний одиночный редактор допустим, но общую шкалу нельзя сохранять цепочкой PATCH.
Не скрывать сетевые ошибки, 401/403/422/500 под fallback. Не добавлять запросы PUT
scale, если backend не поддерживает операцию. Состояние доступности показать понятно.

Локальная интеграция — с проверенным изолированным исходным кандидатом Claude,
не dirty workspace backend и не production. В текущем tgz обнаружены AppleDouble:
до исправления упаковки не считать его готовым релизом. Для стенда допустима
чистая production-база плюс четыре сверенных candidate-files, как в приёмке.
Никакого исполнения скриптов удаления/старта старых PG-стендов вслепую.

Проверить на синтетических данных: старая пересекающаяся шкала → согласованные
границы всех строк → PUT 200 → GET/reload/reopen совпадают; одна версия на save;
invalid/stale не теряют ввод и не меняют сервер; две вкладки; неизменность прочих
полей; manager/superadmin/чужой бизнес. Подтвердить, что одиночный конфликт
не маскируется общим сообщением и что реальное редактирование теперь возможно.
