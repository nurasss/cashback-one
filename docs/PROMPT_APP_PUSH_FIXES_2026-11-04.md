## 1. Иконка уведомления не монохромная

`mobile/android/app/src/main/res/drawable-*/notification_icon.png` — уменьшенная цветная иконка: красный круг с надписью «ONE» на розовом **непрозрачном** фоне. Android рисует иконку уведомления только по альфа-каналу, поэтому в строке состояния будет сплошной белый квадрат.

Исправь:

- иконка — **белый силуэт на прозрачном фоне**: прозрачные пиксели вне знака (alpha 0), белые (`#FFFFFF`) внутри. Подойдёт простой узнаваемый знак (например, монограмма или силуэт логотипа из `assets/icon-foreground.png` по его альфа-каналу, если он есть; иначе — круг с вырезанной надписью). Опиши, что выбрал;
- размеры по плотностям: mdpi 24, hdpi 36, xhdpi 48, xxhdpi 72, xxxhdpi 96 px;
- генерируй скриптом вне репозитория (Pillow есть в `backend/.venv`), исходники `assets/` не менять;
- проверка в отчёте: для каждого файла размер, доля прозрачных пикселей, все непрозрачные пиксели белые (выведи уникальные цвета непрозрачных пикселей), и покажи xxxhdpi-иконку на тёмном фоне в снимке `reports/app-push-2026-11-04/notification-icon-preview.png`.

## 2. Удаление токена при сбросе сессии

`unregisterPushToken` вызывается и из `logout()`, и из `invalidate()`. `invalidate()` срабатывает в том числе, когда сервер отклонил токены (refresh не удался, повторный 401 в `ApiClient`). В этот момент `DELETE /me/push-token` с недействительным токеном доступа сам получит 401, пойдёт в `refresh()`/`invalidate()` и может ждать сам себя до таймаута или запускаться повторно.

Исправь: `DELETE /me/push-token` выполнять **только при явном выходе** (`logout()`). При `invalidate()` из-за отказа авторизации — не обращаться к серверу, только очистить локально сохранённый push-токен и время регистрации, чтобы после следующего входа регистрация прошла сразу (сервер перенесёт токен на нового владельца).

Тесты:

- refresh не удался → `invalidate` завершается без запроса `DELETE /me/push-token`, без повторных `invalidate`, быстрее чем за 1 секунду (фейковые таймеры), локальная запись push очищена;
- `logout` → ровно один `DELETE /me/push-token` до `/auth/logout`, ошибка или зависание DELETE не задерживают выход больше 3 секунд;
- после `invalidate` и нового входа → сразу `PUT /me/push-token`, без ожидания суток.
