## Что должно измениться — и что проверить

0.2.2 начинает принимать номера карт **4–13 цифр**. В тестовой ONE 5 карт с номерами из 4–5 цифр до сих пор пропускались. Ожидается:

1. `--version` → **0.2.2**, в логе `Starting POSCENTER Loyalty Agent v0.2.2`, POS-сервис выключен, порт 8765 закрыт.
2. **Первый цикл после старта:** `ONE read completed: type=cards_snapshot, records_read=1710, changes_to_send=5, skipped_invalid_barcode=2 (empty=0, non_digits=2, too_short=0, too_long=0), …` — **5 новых карт** уходят в облако. Дальше должна быть строка об успешной отправке карт без ошибок.
3. **Следующие циклы:** `changes_to_send=0`, `skipped_invalid_barcode=2 (… non_digits=2 …)`.
4. `transactions_window` во всех циклах без ошибок. Если у новых карт есть движения, `changes_to_send` по операциям может быть больше 0 — перепиши как есть.
5. **СТОП и сразу сообщить владельцу и куратору** (откат не начинать самостоятельно):
   - любая ошибка отправки (`422`, `CloudNonRetryableError`, `CLOUD_*`, `Unexpected sync error`, Traceback);
   - `changes_to_send` по картам **не 5** в первом цикле;
   - `too_short` ≠ 0.
6. `status` (через владельца): курсоры `set`, `Last Error: (none)`.
7. Ждать **не меньше 12 минут**, минимум два цикла.

Облако (версия 0.2.2, **1709 карт**, операции — 9747 плюс движения новых карт, если они есть, свежий heartbeat, пустой `last_error`) проверяет **куратор**.
