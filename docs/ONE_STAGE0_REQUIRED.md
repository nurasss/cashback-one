# POSCENTER ONE Stage 0 Discovery Requirement

> [!IMPORTANT]
> **Real POSCENTER ONE metadata mapping is NOT implemented.**
> **Exact 1C object names must be discovered from a pilot ONE database.**

---

## 1. Контекст и нормативное ограничение

В соответствии с разделом 1 ТЗ `TZ_loyalty_app_v1.1` и архитектурными инвариантами проекта POSCENTER Loyalty:
* **POSCENTER ONE (1С:Предприятие 8.3)** является единственным источником правды для бонусных балансов и транзакций.
* Облачный бэкенд хранит зеркало данных, синхронизируемое через локальный Windows Agent по COM-интерфейсу (`V83.COMConnector`).
* Точные имена объектов метаданных 1С (справочник карт, реквизиты штрихкода, телефона, ФИО, регистр накопления бонусов, реквизиты регистраторов) **не зафиксированы** в исходном ТЗ и могут различаться в зависимости от релиза конфигурации ONE.

---

## 2. Запрет на предположительные имена метаданных

В кодовой базе Windows Agent (`agent/`) категорически запрещено использовать гипотетические или предполагаемые имена объектов 1С, такие как:
* `connection.Справочники.ДисконтныеКарты`
* `connection.Справочники.ИнформационныеКарты`
* `connection.РегистрыНакопления.Бонусы`
* `connection.РегистрыНакопления.БонусныеБаллы`

**Правило:** Если точное имя объекта метаданных не подтверждено на этапе Stage 0 Discovery, оно не существует для кода системы.

---

## 3. Чек-лист Discovery для пилотной базы POSCENTER ONE (Stage 0)

Для реализации реального адаптера в задаче **TASK-009** инженер интеграции должен зафиксировать в пилотной базе 1С:
1. **Справочник карт:**
   - Точное имя справочника (например, `Справочники.БонусныеКарты` или `Справочники.КартыЛояльности`).
   - Имя реквизита штрихкода (строка EAN-13, 13 цифр).
   - Имя реквизита привязанного номера телефона.
   - Имя реквизита ФИО владельца.
   - Реквизит признака блокировки (`ПометкаУдаления` / `Заблокирована`).
   - Реквизит версии/метки изменения для дельта-синхронизации (или `ВерсияДанных`).
2. **Бонусный баланс:**
   - Имя регистра накопления остатков бонусов (тип: остаточный регистр).
   - Измерения регистра (например, `КартаЛояльности` / `Клиент`).
   - Ресурс остатка (например, `Количество` / `СуммаБонусов`).
3. **История движений (транзакции):**
   - Регистр движений бонусов (начисления, списания).
   - Поля регистратора (документ продажи/возврата/ручной корректировки).
   - Поле уникального идентификатора движения (`НомерСтроки`, `GUID` записи) для формирования стабильного `external_id`.
   - Дата и время движения (`Период`).
   - Сумма начисления / списания.
   - Реквизиты чека / магазина.

---

## 4. Поведение Agent по умолчанию

До завершения Stage 0 Windows Agent функционирует с адаптером по умолчанию:
```text
ONE_ADAPTER_MODE=stub
```
В этом режиме агент запускает сервис, выполняет Heartbeat в Cloud API, а попытка выгрузки карт или транзакций завершается контролируемым статусом:
`ONE_MAPPING_NOT_CONFIGURED: Real POSCENTER ONE metadata mapping is not yet configured. See docs/ONE_STAGE0_REQUIRED.md`.

Фейковые данные в production-окружении не генерируются.
