# KONS2: проверка `СуммаЧека` в ONE только чтением — 2026-11-18

## Зачем

Владелец решил показывать в кабинете, в истории начислений и списаний, колонку «Сумма чека» для каждой операции. Сейчас агент передаёт по операции только сумму бонусов и остаток. Кандидат на источник — реквизит `СуммаЧека` в `РегистрНакопления.ОстаткиБонусныхКарт`, в той же строке, которую агент уже читает. Он нигде не проверен. Перед доработкой агента нужно на тестовой базе узнать:

1. Есть ли `СуммаЧека` в регистре, какой у неё тип и заполнена ли она: у начислений, у списаний, у каких типов документов-регистраторов.
2. Одна строка регистра — это один чек, или одна сумма чека повторяется в нескольких строках (например, по позициям)? Если повторяется, простое суммирование завысит оборот.
3. Похожа ли `СуммаЧека` на итог чека, от которого считались бонусы: доля начисленных бонусов от `СуммаЧека` должна группироваться около процентов статусов (2/3/4/5%).
4. Сидит ли списание бонусов в той же «точке» (регистратор + карта + время), что и начисление по тому же чеку.
5. Есть ли в ONE отдельный документ чека, который пишет движения в этот регистр (`Документ.Чек`), или регистратор — только `ОтчетКассовойСмены` за всю смену.

Это исследование. Агент не обновляется, EXE не собирается, облако не затрагивается.

## Что запустить

**Изменение 18.11 после первой остановки.** Первый запуск остановился правильно: `.env.service` доступен только SYSTEM и администраторам. Скрипт исправлен и файл службы больше не читает. Подключение — как при Stage 0-профиле 27.10: строку подключения вводит **владелец** скрыто, только в своём окне PowerShell. Исполнитель эту строку не видит и не читает.

Прочитай скрипт целиком до запуска. Он:
- подключается к ONE через `OneComConnector` только по переменной `ONE_CONNECTION_STRING` текущего окна PowerShell, строку не печатает;
- выполняет только фиксированные запросы `ВЫБРАТЬ`: агрегаты по регистру и до 60 строк одного последнего регистратора;
- пишет `probe.json` и `probe.md` с количествами. Карты в отчёте — метки C1, C2…, номера карт, телефоны, имена, номера документов и GUID не выводятся.

Исполнитель проверяет скрипт и передаёт владельцу эти шаги. Выполняет их **владелец в своём окне PowerShell**, из корня проекта:

```
$s = Read-Host 'Строка подключения ONE' -AsSecureString
$env:ONE_CONNECTION_STRING = [Runtime.InteropServices.Marshal]::PtrToStringUni([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))
C:\cashback-venv\Scripts\python.exe docs\tools\receipt-amount-probe\probe_receipt_amount.py --out reports\receipt-amount-probe-kons2-2026-11-18
Remove-Item Env:ONE_CONNECTION_STRING
```

Формат строки для тестовой файловой базы: `File="C:\1C_data\int";Usr="<пользователь>";Pwd="<пароль>";` — существующий пользователь 1С с правом чтения. Строку не выводить на экран и не записывать в файлы.

После запуска исполнитель разбирает готовые `probe.json` и `probe.md`. Если подключение не удалось, `poscenter_loyalty_agent` не импортируется или COM не зарегистрирован — СТОП, сырой вывод без секретов. Не трогай `.env.service`, права, ACL и `sys.path`, не устанавливай пакеты без согласования.

Раздел с ошибкой (`"error"`) не останавливает остальные. Не исправляй запросы сам: приложи текст ошибки в отчёт.
