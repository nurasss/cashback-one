## Зачем

Приложение покупателя показывает динамический QR `C1…`: подписанный токен, живёт 60 секунд. Облако умеет превращать его в номер карты: `POST {cloud}/agent/qr/resolve`, заголовок `X-Agent-Key`, тело `{"token":"C1..."}` → `200 {"card_id","barcode"}`; просроченный или поддельный токен → `422 QR_TOKEN_INVALID` (`docs/AGENT_API.md` §2.5, `backend/app/api/agent_pos.py:26`).

Касса **POSCENTER Cash** — это **отдельное устройство** в локальной сети магазина. Наш агент работает на другом компьютере, где стоит ONE. Ключ агента (`AGENT_API_KEY`) на кассу попадать **не должен**. Поэтому агент получает маленький локальный HTTP-сервис: касса шлёт ему токен по сети с отдельным паролем кассы, агент сам спрашивает облако своим ключом и возвращает кассе только номер карты. Дальше касса работает с картой как с обычным штрихкодом.

Доработку самой кассы (1С) делают разработчики Cash. От нас — сервис в агенте, пример кода 1С и инструкция для них.

### 2. Сервис

- **Только стандартная библиотека** для HTTP-сервера: `http.server.ThreadingHTTPServer` в фоновом daemon-потоке, его запуск и остановка вместе с runtime и Windows-службой. Если считаешь, что нужна новая зависимость (например, aiohttp), — СТОП и объясни: она меняет PyInstaller-сборку. Для обращения к облаку используй синхронный `httpx.Client` с тем же `agent_cloud_base_url` и `X-Agent-Key`, что у `cloud_client.py`.
- **Маршруты:**
  - `POST /v1/qr/resolve`: тело JSON `{"token": "C1..."}` не больше 1 КБ, `Content-Type: application/json`, заголовок `X-Pos-Token`;
    - ответ `200 {"barcode": "..."}`. Только номер карты, без `card_id`. Ведущие нули сохраняются: это строка;
  - `GET /v1/health` с тем же `X-Pos-Token` → `200 {"status":"ok"}`. Нужен кассе для проверки связи. Облако при этом не вызывать.
- **Проверки по порядку:**
  1. адрес клиента в `AGENT_POS_ALLOWED_NETWORKS`, иначе `403 POS_FORBIDDEN`;
  2. `X-Pos-Token` сравнивается через `hmac.compare_digest`, иначе `401 POS_UNAUTHORIZED`;
  3. ограничение частоты: не больше 60 запросов в минуту с одного адреса и не больше 10 неверных паролей в минуту с адреса, иначе `429 POS_RATE_LIMITED`;
  4. токен проверяется локально `^C1[A-Z2-7]{20,120}$`, иначе `400 QR_TOKEN_MALFORMED` (облако не дёргать);
  5. запрос в облако.
- **Ответы облака:**
  - 200 → `{"barcode"}`;
  - 422 → `422 QR_TOKEN_INVALID`: касса предлагает покупателю обновить QR;
  - 401/403 от облака → `502 AGENT_NOT_AUTHORIZED` (ключ агента не принят);
  - таймаут или сеть → `504 CLOUD_TIMEOUT` / `503 CLOUD_UNAVAILABLE`;
  - прочее → `502 CLOUD_ERROR`.

  Тело ошибки: `{"error":{"code":"...","message":"..."}}`, message короткий по-русски.
- **Безопасность и логи:**
  - не логировать полный QR-токен, номер карты, `X-Pos-Token`, ключ агента;
  - токен — первые 4 символа и длина, номер карты — последние 4 цифры;
  - стандартный access-лог `BaseHTTPRequestHandler` отключить или заменить своим безопасным;
  - таймаут чтения сокета;
  - `Server`-заголовок без версии Python.
- **Повторов нет.** Повтор к облаку не делать: токен живёт 60 секунд, а касса ждёт ответа сейчас. Отказ облака — сразу ошибка кассе.
- **Изоляция.** Сервис не трогает ONE, SQLite-состояние, курсоры и HMAC-ключи. Синхронизация и heartbeat работают как раньше. Падение HTTP-сервиса не роняет синхронизацию, и наоборот.
- **`status`.** Команда `status` показывает «POS-сервис: включён/выключен, адрес:порт» без секретов.

### 3. Тесты (`agent/tests/`)

На локальном порту `127.0.0.1:0` с подменённым облаком (httpx `MockTransport` или фейковый сервер), **без реального облака**:
- 200 с сохранением ведущих нулей;
- 401 без пароля и с неверным паролем;
- 403 с адреса вне списка (подмени проверку адреса через настройку `AGENT_POS_ALLOWED_NETWORKS`, например только `10.0.0.0/8` при запросе с 127.0.0.1);
- 400 на кривой токен (облако не вызвано);
- 422 проброс;
- 401 от облака → 502;
- таймаут облака → 504;
- 429 при превышении;
- тело больше 1 КБ → 413;
- `GET /v1/health`;
- выключенный по умолчанию сервис не открывает порт;
- `check-config` отклоняет включение без пароля или с коротким паролем;
- в логах нет токена, пароля, ключа и полного номера карты (`caplog`).
