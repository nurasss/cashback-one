## 1. Активные ссылки

В тексте уведомлений внутри приложения и описании акций обычные вставленные ссылки `https://...` и `http://...` распознаются и открываются по нажатию во внешнем браузере. Владелец вставляет URL в существующее текстовое поле кабинета; менять backend или требовать HTML не нужно. `www.` допустимо нормализовать в https, если реализовано корректно; обязательно документировать поддерживаемые форматы. Markdown-редактор и HTML-рендерер не нужны.

Файлы: `mobile/app/(app)/(tabs)/notifications.tsx`, `mobile/app/(app)/promotion/[id].tsx`; общий небольшой компонент ссылочного текста в mobile. Сохранить текст вокруг ссылки, переносы строк, несколько ссылок, Unicode и пунктуацию после URL. Обычный текст без ссылки выглядит как раньше. Ссылки различимы в обеих темах (подчёркивание/цвет), доступны экранному диктору и для нажатия. Внешний `accessible` контейнер уведомления не должен скрывать дочерние ссылки от accessibility.

Разрешать только web URL, не запускать javascript/data/file/intent и другие произвольные схемы. Ошибку открытия обработать без падения, с понятным RU/KK-сообщением. Не отправлять токены API во внешний браузер, ссылки не открывать автоматически при получении уведомления.

Речь о тексте в приложении: произвольные кликабельные фрагменты внутри системного Android push не обещать. Нажатие самого push по-прежнему открывает существующий экран уведомлений; оттуда пользователь нажимает ссылку. Доставку и подтверждение кодов списания не менять.

## 2. Вкладка «Акции»: шесть карточек

Сейчас PromotionsScreen берёт `promotions.data.offers` и строит сетку по две карточки. Владелец называет их баннерами. На вкладке «Акции» первоначально показывать **первые 6 карточек акций в серверном порядке**, максимум три ряда. При количестве >6 под ними кнопка **«Смотреть все»** (RU/KK), по нажатию показывать весь доступный список на этом же экране; допустима кнопка «Свернуть» для возврата к первым шести. При 0–6 кнопки «Смотреть все» нет. Не менять баннерную карусель главной.

Сохранить исходный порядок/фильтрацию API, открытие описания, pull-to-refresh, кеш, состояния загрузки/ошибки, отметки просмотра и отступ под нижнее меню. Не ограничивать запрос API шестью и не обрезать офлайн-кеш. Проверить, не ограничен ли список уже на сервере: если API не отдаёт все акции, записать блокер, backend самостоятельно не менять. Не терять выбранный режим при простой перерисовке/смене темы; при смене аккаунта или бизнеса не переносить его и данные прежнего клиента.

На фото владельца обведён старый маленький знак слева от «Keremet Bonus» на экране блокировки. Нужен узнаваемый новый знак KeremEt, соответствующий актуальной основной иконке, а не старая ONE. Проверить реальные ссылки ресурсов и flavor overlays:

- `mobile/app.json`: expo-notifications сейчас указывает общий `assets/icon-foreground.png`.
- `mobile/android/app/src/main/AndroidManifest.xml`: FCM и Expo default_notification_icon ссылаются на `@drawable/notification_icon`.
- Новая иконка Keremet — `mobile/clients/keremet/android/res/mipmap-*/ic_launcher*`, badge — `mobile/clients/keremet/header_badge.png`, логотип — Logo.tsx. Использовать существующий новый знак, не генерировать новую эмблему.
- Backend FCM сейчас задаёт channel_id, не задаёт icon. Backend не менять.

Android small icon использует одноцветный силуэт/альфа-маску: сделать белый знак на прозрачном фоне из нового символа KeremEt без непрозрачной квадратной/круглой подложки, чтобы он не превращался в сплошной кружок. Цвет и форму контейнера может определять ОС; полного совпадения с цветной launcher-картинкой на всех телефонах не обещать. Официальная справка: https://developer.android.com/design/ui/mobile/guides/home-screen/notifications

Добавить постоянные клиентские ресурсы notification_icon в `mobile/clients/keremet/android/res/` и обеспечить попадание в настоящий flavor при будущей сборке; проверить build-client.sh/Gradle только по необходимым местам. Изменения только app.json без актуального native resource недостаточно: prebuild не запускать. Общий Cashback One должен использовать свой актуальный ONE-знак, Keremet — свой. Launcher-иконку, пакеты, подпись, разрешения, Firebase и channels не менять. Если для устойчивой подготовки нужна адаптация скрипта копирования клиентских ресурсов, сделать минимально и описать, без запуска сборки/подписания.
