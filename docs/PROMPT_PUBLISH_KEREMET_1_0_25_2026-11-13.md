## Порядок публикации

1. Проверь локальный APK: размер, полный SHA-256, пакет, версию и подпись.
2. Проверь состояние хостинга и наличие целевого имени через FTPS-листинг. HTTP 200 сам по себе не доказывает наличие APK: отсутствующие пути могут возвращать HTML.
3. Скачай текущий клиентский манифест, сохрани копию вне публичной папки с правами 0600; запиши её путь и полный SHA-256.
4. Ожидаемый прежний манифест: `latest_version=1.0.24`, `latest_version_code=25`, `min_version_code=1`, `download_url=https://cashback-qr.poscenter.kz/app/keremet-cashback-1.0.24.apk`. Последний независимо проверенный SHA-256: `dc0216c216e55c021f12814c800976f9bea7e744154082800c793e2f3024e63f` (173 байта).
5. Зафиксируй контрольные хеши общего `app/version.json`, главной страницы и предыдущего APK 1.0.24. Для 1.0.24 ожидаются **67 959 385 байт**, SHA-256 `a51bf9692cc97ff883f28b3281663cb5f4d8cc1472dbca13015305401931b03b`.
6. Загрузи новый APK под уникальным временным именем, скачай его обратно по FTPS целиком, сравни размер и SHA-256. После совпадения переименуй в `keremet-cashback-1.0.25.apk`.
7. До переключения манифеста полностью скачай APK по HTTPS: проверь HTTP, MIME `application/vnd.android.package-archive`, размер и полный SHA-256.
8. Подготовь JSON ниже. Непосредственно перед переключением повторно проверь, что прежний публичный манифест не изменён другим исполнителем.
9. Загрузи манифест через уникальное временное имя, проверь обратным чтением и переключи штатным переименованием. Не удаляй действующий манифест ради обхода ошибки.
10. Снова скачай публичный манифест и APK по HTTPS целиком. Проверь JSON и значения, URL, HTTP/MIME, размер и полный SHA-256. Не ограничивайся HEAD, ETag или Content-Length.
11. Проверь контрольные хеши до/после. Старые файлы должны сохраниться. Зафиксируй листинг `app/` и отсутствие собственных временных файлов после успешного переименования; чужие файлы не подчищай.
12. Сохрани отчёт и дай владельцу ссылку на опубликованный APK.

Если состояние не соответствует ожидаемому — СТОП до перезаписи.
