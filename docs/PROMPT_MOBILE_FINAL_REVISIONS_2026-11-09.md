## A. Исправить заставку до любых новых тестов/сборки

Сохранить проверки duration <=5, типа/версии/бизнеса. Добавить валидные fixture-ответы с реалистичными размерами >10000, граничные 5/15 MiB и превышения. Старые 19 падений не скрывать заменой входов на файлы менее 10 КБ.

Проверить appSplash и связанные тесты одним прогоном, typecheck. Успешный этап допускает дальнейшую работу без отдельного разрешения. ## B. Четыре новые правки владельца

1. Во всех собственных RU-текстах интерфейса заменить понятие «баллы» на «Бонусы» с правильными формами: «Бонусы», «Сумма бонусов», «Начислено бонусов», «Списано бонусов» и т.д. Не делать слепую замену во входящих серверных описаниях, названиях, API, именах полей и расчётах. KK — согласованная терминология интерфейса, существующий язык не превращать в русский.
2. Убрать служебный номер сборки в скобках в профиле и настройках (сейчас «Версия 1.0.18 (19)»). Оставить читаемую версию без скобок; проверка обновлений продолжает использовать настоящий native versionCode, не удалять его из логики.
3. Не показывать тиыны/дробную часть у баланса, начислений/списаний и денежных сумм интерфейса. Только отображение: исходные Decimal/API/расчёт оборота/порогов не менять. Отображение целых с отсечением дробной части к нулю, включая отрицательные; разделители тысяч и +/- сохраняются, для остатка меньше единицы не рисовать «-0». Проценты не округлять до целых автоматически. Дробные значения остаются в данных. Протестировать 0, 0.99, -0.99, 1234.56, -1234.56 и длинные Decimal без потери точности Number.
4. На экране «Ваш статус» добавить список магазинов: название/адрес, нажатие открывает существующий map_url. На главной под карточкой статуса ссылка «Где я могу потратить свои бонусы?» ведёт непосредственно к списку (отдельный route или якорь в status, без дублирования источника магазинов). Доступен и без карты, если app-content этого клиента доступен.

Расстояния: приблизительное расстояние ПО ПРЯМОЙ от текущего местоположения до координат магазина, подпись «По прямой», метры/километры. Не обещать длину маршрута. Использовать только foreground location после осмысленного действия пользователя; без запроса при холодном запуске, без фонового слежения и отправки координат пользователя серверу. Отказ/отключённая геолокация/нет координат магазина не ломают список: показать адрес и «Расстояние недоступно», а не 0 км. Повторный запрос разрешения не зацикливать. Нужную permission/dependency для явно заказанной геолокации описать, не добавлять background/audio. API получать по Context7.

Сейчас у BusinessStore нет latitude/longitude — Gemini готовит nullable координаты в отдельной задаче. Не извлекать произвольные координаты из текста адреса или map_url, не выдумывать маршрут/платную геокодировку. Типы подготовить совместимо со старым ответом, точные поля согласовать с принятым контрактом Gemini. Реальные расстояния нельзя объявить готовыми, пока координаты не появились.
