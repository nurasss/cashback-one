# Cashback One — инструкции для следующего куратора

Состояние зафиксировано 2026-10-21. Относится ко всему репозиторию. Явные поручения пользователя имеют приоритет. Исторические показатели не заменяют проверку текущего состояния.

## 1. Роль и порядок работы

Ты продолжаешь как куратор проекта. Общайся по-русски, коротко и понятно. Сначала прочитай целиком `CLAUDE.md` и `docs/HANDOFF_2026-10-21.md`. Полная история — `docs/HANDOFF_2026-10-19.md`; поздние записи отменяют устаревшие ранние статусы.

Исполнители:

- **Gemini(app)**: приложение, Android/APK и подпись.
- **Gemini(exe)**: Windows EXE/служба, PyInstaller, Inno Setup.
- **Gemini(general)**: COM-адаптер, backend, админка, остальные задачи.

Промпты самодостаточные, на русском: цель, файлы для чтения, допустимые действия, ограничения, критерии, проверки и путь отчёта. Пользователь переносит промпты и приносит результаты. Обязательное правило: **«Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть»**. Отчёт сохранять в файл: длинный чат обрезается. Не назначай повторно уже использованный номер.

Независимо проверяй отчёт: читай файл и `git diff`, запускай подходящие тесты/ruff, проверяй факты SQL READ ONLY, API и хешами. Mock-тест не равен настоящей интеграции. Если baseline упал до правок, зафиксируй и сообщи; не прячь ошибку изменением фикстур.

Куратор сам выполняет проверки чтением. Документы, deploy админки/backend, коммиты/push и Releases делались по прямым поручениям пользователя. Учитывай уже данные разрешения и не запрашивай их повторно для порученных действий. Для новых изменений production ориентируйся на текущую задачу, а не на прошлое разрешение. Сохранение контекста не означает запуск новой разработки или испытаний с побочными эффектами.

## 2. Данные и принятые решения

- **1С только на чтение.** Не создавать документы/движения, не изменять конфигурацию, не регистрировать COM автоматически. Кассовый тест выполняет пользователь/кассир штатными средствами.
- ONE — источник правды, облако — зеркало. Не правь облачный баланс для обхода ONE.
- Номер карты — строка **6–15 цифр**, ведущие нули сохранять. Отрицательные балансы передавать как есть.
- Обычный штрихкод — номер карты. Динамический QR `C1…` требует `POST /agent/qr/resolve`. Доработка Cash для обычного штрихкода пока не признана обязательной: сначала сканирование.
- WhatsApp OTP нужен для входа покупателя. Кодов подтверждения списания **нет**.
- Движения Cash поступают в ONE при закрытии смены. Не обещай обновление приложения сразу после чека.
- У каждого клиента свои бизнес, ключ, ONE и состояние. Нельзя переключать существующую SQLite на другого клиента/базу без процедуры миграции.
- Не удалять/не сбрасывать SQLite, курсоры, HMAC и конфиг. Базу и HMAC-ключ сохранять вместе.
- Не просить/не выводить API-ключи, пароли, строку подключения, `.env.service`, HMAC, signing keys и персональные данные. Не передавать секреты аргументами процессов.
- Не ослаблять ACL для диагностики. Отказ чтения неповышенной консоли ожидаем. Не завершать чужие процессы и не подчищать последствия инцидентов самостоятельно.
- Не публиковать рабочие DB, Stage 0 outputs, клиентский маппинг, бэкапы, конфиги и ключи. Исходники в Git, APK/EXE в Releases.

## 4. Что не сделано и ближайший шаг

Следующий продуктовый шаг: узнать доступность Cash, подключённую ONE и возможность контролируемого теста. Агент сейчас читает тестовую `int`. Нужна карта, реально существующая в той же ONE; облачная seed-карта для кассы не подходит.

Не подтверждены:

1. Штрихкод приложения → Cash → штатные начисление/списание → закрытие смены → ONE → агент → облако → приложение, с правильным балансом и без дублей.
2. Перенос новых штатных изменений ONE установленной EXE-службой после кассового теста. Повторное чтение пустой дельты уже доказано.
3. Реальное восстановление после аварийного завершения и разрыва сети. Recovery настроен, crash-тест не выполнен.
4. Подключение реального клиента: бизнес/ключ, база/маппинг, read-only пользователь, доступ LocalSystem, COM/лицензия, доступность компьютера.
5. Регулярные защищённые копии и проверка восстановления. Имеющаяся разовая копия не равна отработанному восстановлению.
6. Замена ранее раскрытого пароля `loyalty_ro`, защищённая копия Android signing keys, исключение `.git`/`.stfolder` из Syncthing на обеих машинах.

Отложены Wallet, App Store/Google Play, динамический QR Cash, Authenticode EXE. Открытые решения: подпись об обновлении после смены; отображение массового списания 2026-09-06; обновление demo и устаревшего текста `docs/WALLET.md`. В рамках сохранения контекста не внедрять.
