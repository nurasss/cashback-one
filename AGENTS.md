# Cashback One — инструкции для следующего куратора

Обновлено 2026-11-09 по решениям и хронологии `CLAUDE.md` до 2026-11-07. Отдельно отмечен более поздний отчёт частичной выкладки. Это сводка документированных результатов, а не новая проверка production. Относится ко всему репозиторию. Явные поручения пользователя имеют приоритет. Исторические показатели не заменяют проверку текущего состояния.

## 1. Роль и порядок работы

Ты продолжаешь как куратор проекта. Общайся по-русски, коротко и понятно. Сначала прочитай целиком `CLAUDE.md` и `docs/HANDOFF_2026-10-21.md`. Полная история — `docs/HANDOFF_2026-10-19.md`; поздние записи отменяют устаревшие ранние статусы.

**Решение владельца 2026-11-02:** куратор сам не правит код продукта, даже мелочи. Это отменяет прежнее «мелкие задачи куратор делает сам». Куратор готовит промпты и независимо принимает результат; документы обновляет по поручению владельца.

Исполнители (решение владельца 2026-10-22; прежние роли Gemini(app) и GPT(app) отменены):

- **Claude**: приложение, Android/APK и подпись.
- **Gemini**: сайт (лендинг, вход, кабинет), backend, агент и COM-адаптер, Windows EXE/служба (PyInstaller, Inno Setup), деплой и остальные задачи.

Порядок: куратор выдаёт промпт → владелец передаёт исполнителю → приносит вывод → куратор независимо проверяет.

Промпты самодостаточные, на русском: цель, файлы для чтения, допустимые действия, ограничения, критерии, проверки и путь отчёта. Пользователь переносит промпты и приносит результаты. Обязательное правило: **«Упало или неожиданно — СТОП и сырой вывод; без самостоятельных исправлений и повторных мутаций; секреты и персональные данные скрыть»**. Отчёт сохранять в файл: длинный чат обрезается. Не назначай повторно уже использованный номер.

Независимо проверяй отчёт: читай файл и `git diff`, запускай подходящие тесты/ruff, проверяй факты SQL READ ONLY, API и хешами. Mock-тест не равен настоящей интеграции. Если baseline упал до правок, зафиксируй и сообщи; не прячь ошибку изменением фикстур.

Куратор сам выполняет проверки чтением. Документы, deploy админки/backend, коммиты/push и Releases делались по прямым поручениям пользователя. Учитывай уже данные разрешения и не запрашивай их повторно для порученных действий. Для новых изменений production ориентируйся на текущую задачу, а не на прошлое разрешение. Сохранение контекста не означает запуск новой разработки или испытаний с побочными эффектами.

## 2. Данные и принятые решения

- **1С только на чтение.** Не создавать документы/движения, не изменять конфигурацию, не регистрировать COM автоматически. Кассовый тест выполняет пользователь/кассир штатными средствами.
- ONE — источник правды, облако — зеркало. Не правь облачный баланс для обхода ONE.
- Номер карты — строка **4–13 цифр** (с 2026-10-24; ранее 6–15), ведущие нули сохранять. Правило одинаково в backend, агенте (с 0.2.2), POS-сервисе, кабинете и приложении (с 1.0.6). Агент пропускает номера ONE вне правила и считает их в `skipped_invalid_barcode`; исправлять такие номера в самой ONE. Отрицательные балансы передавать как есть.
- **Курс с 2026-11-04:** каждому клиенту отдельный APK на общем сервере. Общая кодовая база — `mobile/`, отличия — `mobile/clients/<slug>/`, Gradle flavors и `EXPO_PUBLIC_CLIENT`; не делать копии приложения. Один ключ подписи для всех клиентов — решение владельца. План: `docs/ROADMAP_PER_CLIENT_2026-11-04.md`, раздел 5а важнее раздела 6.
- Текущий QR по новому курсу — **статичный номер карты**. Динамический `C1…` и агентский LAN-резолвер относятся к прежней архитектуре; посредник в агенте отменён. Касса обращается прямо в облако с отдельным `X-Pos-Key`, ключ агента кассе не передавать.
- WhatsApp OTP используется для входа. **Списание подтверждается 4-значным кодом через push в приложение; без приложения списание не проводится.** Старое утверждение «кодов списания нет» отменено. В актуальном сценарии `/pos/code-push` Cash (1С 7.7) сама генерирует и сверяет код, облако только доставляет его. Ранее реализованные `/pos/redemptions` и `/pos/redemptions/{id}/verify` сохранены; не смешивать эти сценарии. Контракт: `docs/POS_REDEEM_API.md`, функция Cash: `docs/integrations/cash77_code_push.txt`.
- **Решение 2026-11-06:** карты подключаются автоматически по телефону, ручного добавления в приложениях нет. Без карты показывать «Карта с вашим номером телефона не найдена в базе магазина. Пожалуйста, обратитесь в магазин.». Баннеры, акции, тексты, магазины и рассылки клиента доступны без карты; карта нужна для баланса, статуса, истории и QR. Общие рекламные баннеры платформы — в общей карусели; общие `offer` в приложения клиентов не попадают.
- Push бизнеса с `android_app_id` направляются **только в его приложение**; без него — в общее приложение владельцев карты. Аудитория «Все бизнесы» — все. У `keremet` по последней записи `android_app_id=kz.cashbackone.keremet`.
- Движения Cash поступают в ONE при закрытии смены. Не обещай обновление приложения сразу после чека.
- У каждого клиента свои бизнес, ключ, ONE и состояние. Нельзя переключать существующую SQLite на другого клиента/базу без процедуры миграции.
- Не удалять/не сбрасывать SQLite, курсоры, HMAC и конфиг без отдельной согласованной процедуры с копией. Выполненный сброс Keremet не разрешает повторять его. Базу и HMAC-ключ сохранять вместе. С агента 0.3.0 ключ и пароль 1С защищены DPAPI; откат на 0.2.2 требует возврата `.env.service` из копии. Ключ агента показывается один раз; действие кабинета — «Перевыпустить ключ».
- Не просить/не выводить API-ключи, пароли, строку подключения, `.env.service`, HMAC, signing keys и персональные данные. Не передавать секреты аргументами процессов.
- Не ослаблять ACL для диагностики. Отказ чтения неповышенной консоли ожидаем. Не завершать чужие процессы и не подчищать последствия инцидентов самостоятельно.
- Не публиковать рабочие DB, Stage 0 outputs, клиентский маппинг, бэкапы, конфиги и ключи. Исходники в Git, APK/EXE в Releases.
