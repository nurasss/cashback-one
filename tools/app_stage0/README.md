# APP Stage 0: read-only исследование ONE

Инструмент инвентаризирует метаданные и собирает агрегаты для POSCENTER APP. Он не
записывает данные в ONE и не запускает/не меняет службу лояльности. Эвристический
кандидат **не является подтверждённым маппингом**. Работа через настоящий COM и
совместимость запросов с конкретной конфигурацией ещё не подтверждены.

На тестовом Windows запускать только после приёмки части А и получения кода в `main`.
Владелец сам вводит `ONE_CONNECTION_STRING` в окружение своего процесса и запускает
команды. Не выводить строку, не записывать её в файл и не передавать аргументом.
Нужен существующий x86 Python с pywin32; устанавливать зависимости не требуется.
Папка результатов обязательна и должна быть **вне репозитория**. На Windows UNC,
сетевые диски и диски неопределённого типа отклоняются.

```powershell
$env:PYTHONPATH = 'agent/src'
& 'C:\cashback-venv\Scripts\python.exe' tools/app_stage0/app_stage0.py metadata --output-dir 'C:\cashback-stage0\app-stage0-result'
```

В `metadata.json` перечислены имена и синонимы семи категорий, детали кандидатов,
поля, похожие на даты создания/изменения, и доступный состав планов обмена.
Ошибки доступа к отдельным свойствам помечены как недоступные, а не как пустые.
Составить `targets.json` **по реальным именам из метаданных**, не по примеру ниже.
Все поля и табличные части повторно сверяются с метаданными подключённой базы.

Формат примера (имена условные, не утверждают существование объектов ONE):

```json
{
  "targets": [
    {
      "kind": "document",
      "name": "ИмяДокументаИзМетаданных",
      "sections": ["ИмяТабличнойЧастиИзМетаданных"],
      "benchmark_sections": ["ИмяТабличнойЧастиИзМетаданных"],
      "payments": [{
        "section": "ИмяТабличнойЧастиИзМетаданных",
        "field": "ИмяПоляОплатыИзМетаданных",
        "allowed_values": ["Наличные", "Карта"]
      }],
      "crosscheck_amount_field": "ИмяПоляСуммыИзМетаданных"
    },
    {"kind": "register", "name": "ИмяРегистраИзМетаданных", "register_kind": "balance"},
    {"kind": "register", "name": "ИмяРегистраОборотовИзМетаданных", "register_kind": "turnover"},
    {"kind": "catalog", "name": "ИмяСправочникаИзМетаданных", "barcode_fields": ["ИмяПоляИзМетаданных"]},
    {"kind": "information_register", "name": "ИмяРегистраСведенийИзМетаданных"}
  ]
}
```

Все параметры кроме `kind` и `name` необязательны, но для `register` обязателен
`register_kind`, выбираемый по виду регистра в метаданных. Для сверки ровно один
документ должен содержать `crosscheck_amount_field`. Указывать только подходящие
для типа объекта параметры. `sections` — таблицы для статистики строк на документ;
`benchmark_sections` — таблицы для эталонного чтения. Расчёт медианы включает
документы без строк, если общее количество документов успешно прочитано.

`allowed_values` — **явный список согласованных владельцем неперсональных
представлений типов оплаты**, а не имена людей/контрагентов. Значения, не входящие
в список, не выводятся вообще: суммируется только их количество. Это важная
граница, потому что каталог, ошибочно принятый за виды оплаты, может содержать
произвольные личные сведения. Оставьте список пустым, если значения не проверены.
Строку подключения и ПДн в `targets.json` не помещать.

```powershell
& 'C:\cashback-venv\Scripts\python.exe' tools/app_stage0/app_stage0.py profile --output-dir 'C:\cashback-stage0\app-stage0-result' --targets 'C:\cashback-stage0\app-stage0-result\targets.json'
& 'C:\cashback-venv\Scripts\python.exe' tools/app_stage0/app_stage0.py crosscheck --output-dir 'C:\cashback-stage0\app-stage0-result' --targets 'C:\cashback-stage0\app-stage0-result\targets.json' --date YYYY-MM-DD
```

`profile` создаёт `metadata.json`, `profile.json`, `APP_STAGE0_SUMMARY.md`. Каждая
ошибка запроса записывается без произвольных слов и чисел: обычный sanitizer не
умеет надёжно обнаруживать ФИО и части строки подключения. Для диагностики остаются
тип исключения и безопасные слова исходного сообщения. Порог `--slow-query-seconds`
по умолчанию 60 секунд: это **не прерывание** выполняющегося COM-запроса; после
его завершения следующие тяжёлые запросы объекта пропускаются. Эталонные запросы
идут последними, читают все реквизиты выбранной табличной части и не сохраняют их
значения. Периоды эталона считаются от даты последнего документа (запрос
«документы всего»), а не от сегодняшнего дня: «последний день с документами» и
«7 дней по последний день с документами». Если эта дата неизвестна, эталон
помечается «не проверено» и не выполняется.

Если операция прервалась целиком (например, не удалось подключиться к ONE), в
консоль выводится только имя класса ошибки, например
`Операция не выполнена (COMConnectionError)`, без текста ошибки.

Для отпечатка документов задним числом нет доказанной сортировки по созданию:
ссылка и номер могут не отражать время создания. Поэтому инструмент указывает
«не проверено», а не выдаёт косвенный показатель за факт. Виртуальная таблица
остатков может не содержать комбинаций с нулевым остатком. Запрос распределения
длин и числового формата штрихкодов зависит от поддержки функций языком запросов
данной версии ONE; ошибки отображаются без значений. Периоды 24 и 3 месяца
включают текущий неполный календарный месяц.

`crosscheck` пишет только в отдельный локальный `crosscheck-YYYY-MM-DD.json`,
не перезаписывает существующий файл и не выводит числа в консоль. Файл содержит
чувствительные коммерческие данные: не переносить его в репозиторий и отчёт.
Сверка считает все документы выбранного типа за дату и суммирует выбранное поле,
без фильтров проведения, отмены или возвратов. Владелец обязан сопоставить эти
условия с отчётом ONE; автоматическое совпадение не предполагается.

После работы владелец удаляет переменную окружения из своей сессии:

```powershell
Remove-Item Env:ONE_CONNECTION_STRING
```
