## 2. Архитектура и реализация

### А. Верхняя карусель (`BannerCarousel`)
- Ровно один новый локальный баннер (`banner-car-prize.png`) добавлен в начало списка слайдов карусели.
- Серверным баннерам сохранён прежний `aspectRatio: 2.4`, их оформление не менялось (заголовок с цветным первым словом слева, подзаголовок, картинка кампании справа на фоне `#F1F1F4`).
- Пропорция `675 / 294` применяется **только к новому локальному баннеру** (`styles.bannerLocal`).
- Локальный баннер рендерится полноразмерным изображением (`width: '100%', height: '100%', resizeMode: 'contain'`) без дублирования текста, бейджей и стрелок.
- Порядок серверных баннеров API строго сохранён.
- Автопрокрутка (каждые 5 с), свайпы и индикаторы точек (`Dot`) работают, если логических баннеров больше одного (`count > 1`).
- При пустом ответе API (`banners: []`) отображается ровно один локальный баннер (без точек и без зацикленных клонов).
- Нажатие на локальный баннер открывает раздел `/promotions`. Нажатие на любой серверный баннер открывает его страницу `/promotion/[id]`.

### Б. Постоянные карточки «Горячие предложения» (`PermanentOffersGrid`)
- Четыре карточки показываются **ПОСТОЯННО**: независимо от наличия акций в API, состояния загрузки (`isPending`) или ошибки сети (`isError`).
- Ровно 4 карточки в сетке 2×2 с отступами `gap: 12` и `paddingHorizontal: 20`:
  1. Сверху слева: `offer-hits-discount.png` («Скидка на хиты. Покупайте выгодно»);
  2. Сверху справа: `offer-weekly-promo.png` («Акция недели. Товары по лучшим ценам»);
  3. Снизу слева: `offer-card-bonus.png` («Выгодно с картой. Больше бонусов»);
  4. Снизу справа: `offer-fresh-products.png` («Суперцена. Свежие продукты»).
- Точные пропорции: каждая карточка имеет `aspectRatio: 378 / 312`, изображение заполняет 100% карточки без обрезки и искажений (`resizeMode: 'contain'`).
- Карточки имеют микроотклик нажатия `PressScale` (scale 0.98), при нажатии вызывают `router.push('/promotions')`.
- Кнопка «Все» в заголовке секции также ведёт в `/promotions`.

### В. Компоновка главной страницы (`Home`)
- Главная страница обёрнута в вертикальный `ScrollView` (`showsVerticalScrollIndicator={false}`). Карточки больше не сжимаются по высоте `flex: 1` ради вмещения в один экран.
- Сохранён нижний запас под TabBar и системную навигацию: `paddingBottom: TAB_BAR_HEIGHT + insets.bottom + 16`.
- В горизонтальном `Animated.ScrollView` карусели включён `nestedScrollEnabled` для плавных горизонтальных жестов внутри вертикального скролла.

### Г. Сохранность существующих компонентов
- `OfferCard` в `mobile/src/features/home.tsx` полностью сохранён и обслуживает экран `/promotions` для реальных серверных акций.
- Сессия, динамический QR, Code128, сохранение профиля, `useKeyboardLift`, города, TabBar, баланс и плашка задержки не затрагивались.

## 5. Локальный Web-preview и скриншоты

Выполнен локальный запуск web-предпросмотра:
- Сборка бандла выполнена с флагом `EXPO_PUBLIC_DEMO=1`, переданным **исключительно процессу экспорта**, файл `.env` не создавался и не модифицировался.
- В demo-режиме используются встроенные in-memory тестовые данные (`createDemoApi()`). Обращений к реальному API, внешним серверам или настоящим аккаунтам не было.
- Страница открыта через Chrome DevTools с эмуляцией мобильных устройств:
  1. **Обычный экран (390×844)**: верхний баннер виден целиком без обрезки, серверные баннеры карусели сохранены, статус и плашка задержки баланса на месте, заголовок «Горячие предложения» и верхний ряд карточек видны без сжатия.
  2. **Узкий экран (320×640)**: верстка не ломается, карточки сохраняют пропорции 378:312, текст и графика чёткие.
  3. **Прокрутка на узком экране (320×640)**: страница плавно прокручивается вертикально, сетка 2×2 видна целиком, TabBar не перекрывает нижние карточки благодаря запасу `paddingBottom: TAB_BAR_HEIGHT + insets.bottom + 16`.
- **Ограничение**: Web-preview на движке Chrome не является проверкой нативного рендеринга Android (Hermes / Yoga).
