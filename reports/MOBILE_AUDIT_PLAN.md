## 1. Краткий итог

Сильные стороны (по коду):

- Сессия устроена аккуратно. Токены хранятся одной записью в SecureStore (`WHEN_UNLOCKED_THIS_DEVICE_ONLY`), Android backup настроен. Есть ротация refresh с общей промежуточной операцией, защита от ответов прошлой сессии (`epoch`), очистка кэша при выходе и при `invalidate`. В release-сборке HTTP запрещён, тело ошибки сервера не сохраняется.
- Обработаны BUSINESS_SELECTION_REQUIRED и формат карты 6–15 цифр с ведущими нулями. Срок 14 дней в тексте совпадает с `refresh_token_ttl_seconds = 14 * 86400`.
- Ведущие нули и отрицательные балансы форматируются без потерь (`pointsText`). Типы операций агента — только `accrual`/`redemption` с положительной суммой, поэтому знак в истории верен.

Главные риски:

1. **Для кассового пилота приложение не показывает обычный штрихкод карты.** Вкладка QR показывает только динамический токен `C1…`. Cash не умеет его распознавать без отдельной доработки (`POST /agent/qr/resolve`). По тесту видно, что это сознательное решение: «never the barcode». Шаг handoff «показать обычный штрихкод в приложении» сейчас выполнить нельзя.
2. При ответе сети не в формате JSON (Wi‑Fi с авторизацией, прокси) обновление токена **выходит из аккаунта**.
3. Без сети при запуске нельзя ничего посмотреть. Рядом с «Повторить» стоит кнопка «Выйти».
4. Казахский интерфейс показывает ошибки только по-русски.
