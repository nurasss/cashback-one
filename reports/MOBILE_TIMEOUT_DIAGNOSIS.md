## 9. Анализ дефекта: ответ сервера затирает новый ввод того же поля

Только анализ кода (`mobile/app/(app)/(tabs)/profile.tsx`). **Не воспроизведено тестом, исправление не внедрено.**

### Дефект

Строки 50–66, функция `save` (общая кнопка «Сохранить», поля имя и фамилия):

1. Строки 54–57: из текущей формы собирается `body` (разница с серверной копией), например `first_name: 'Аня'`.
2. Строка 61: `await patch(body)`. Во время запроса кнопка отключена, но поля имени и фамилии остаются редактируемыми.
3. Пользователь меняет то же поле на «Анна» (`update`, строка 39: форма получает «Анна», `saved` сбрасывается).
4. Строка 63: по приходе ответа для **каждого отправленного ключа** без условия выполняется `form[key] = fresh[key]`, то есть значением из ответа, где «Аня». Ввод «Анна» теряется.
5. Строка 64: `setSaved(true)` показывает «Профиль сохранён», хотя «Анна» нигде не сохранено.
6. Следствие: форма снова равна серверной копии, и следующее «Сохранить» ничего не отправит, поэтому пользователь потеряет правку без единого сообщения.

Комментарий в коде («anything typed … meanwhile stays as it is») верен только для **других** полей. Мой тест «general save does not overwrite text typed meanwhile» проверяет именно другое поле (`last_name`), поэтому этот случай не покрыт.

`commitField` (строки 68–76) подобным образом не страдает: во время запроса шторка отключает поле ввода и закрытие, форма поля не меняется. Побочный эффект есть, но малозначимый: при ответах, пришедших не по порядку, кэш запроса профиля может временно хранить более старый снимок, из-за чего позже одно поле может быть отправлено повторно (безвредно).

### Предлагаемое исправление (для следующего шага)

Принцип: серверное значение применять к полю, только если поле **не менялось** с момента отправки.

1. Перед `await` сохранить срез отправленных значений: `const sent = Object.fromEntries(Object.keys(body).map(key => [key, form[key as keyof Form]]))` — именно текстовые значения формы, а не нормализованные значения тела.
2. В `setForm(current => …)` для каждого ключа брать `fresh[key]` только если `current[key] === sent[key]` (поле осталось таким, как отправлено, и принимает нормализацию сервера, например обрезку пробелов); иначе оставить `current[key]`.
3. `setSaved(true)` выполнять, только если ни одно отправленное поле не изменилось (сравнить в том же месте по `sent`); иначе оставить `saved = false`. Для этого рассчитать флаг до вызова `setForm` либо читать актуальную форму из `ref`, обновляемого в `update`. Простейший вариант — счётчик правок `editVersion` в `useRef`, увеличиваемый в `update`; сравнить значения до и после запроса.
4. После ответа `original = toForm(profile.data)` уже содержит «Аня» (кэш обновил `patch`), а форма — «Анна», поэтому следующее «Сохранить» отправит `first_name: 'Анна'` без дополнительных действий.
5. При ошибке запроса (`catch`) форму не трогать — так сейчас и есть, ввод сохраняется.
6. Для единообразия можно применить то же условие в `commitField`, но по коду форма поля там не меняется, поэтому это защита «на всякий случай»; делать не обязательно.
