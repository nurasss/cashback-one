# Выкладка backend: вход, профиль, фото — 2026-11-01

По поручению владельца куратор выложил backend из коммита `b30a4f6` на VPS `kz-vps`, `/opt/cashback-one`. Простой — перезапуск контейнера backend.

## Что вошло

- Необязательное поле `code_length` (4 или 6, по умолчанию 6), проверка кода принимает 4 и 6 цифр.
- Лимит неверных кодов по IP: 20 за 600 с. После превышения отказ получает и верный код.
- Правило 18 лет в `birth_date`.
- `POST` и `DELETE /me/avatar`, файлы `media/avatars/<uuid>.webp`.
- Миграция `0011_customer_avatar`: столбец `users.avatar_url`.

## До выкладки

- Исходники на VPS побайтно совпадали с прежним коммитом: 81 файл `backend/app` и `backend/migrations`.
- Архив собран через `git archive`, без `tests`, `.env` и `.venv`. SHA-256 `3f105951…a6f6` сверен на VPS.
- Команда из `docs/DEPLOY_VPS.md` не исключает `.venv`, поэтому не использовалась.
- Значения до выкладки: alembic `0010_customer_app_content`, покупателей 4, карт 1710.

## Копии

- `backups/avatar-20261101T084801Z/`: `pg.sql.gz` (620 331 байт, `gzip -t` успешно, 20 таблиц, строка завершения дампа есть), `env.bak` (600), `backend-src.tgz`.
- Образ отката: `cashback-backend:rollback-avatar-20261101T084801Z` (прежний `local` `07d63096f12c`).

Первый запуск скрипта копий остановился до `env.bak`: проверка смотрела в последние 3 строки дампа, а `pg_dump` дописывает после строки завершения `\unrestrict`. Дамп оказался целым, копии завершены в той же папке.

## После выкладки

- `cashback-migration` Exited (0), `0010 → 0011`. Новый образ `1abde56d6bcf`.
- `/health/ready`: database ok, redis ok. Ошибок в журнале backend нет.
- SQL READ ONLY: alembic `0011_customer_avatar`, `avatar_url` varchar(512) nullable, покупателей 4, карт 1710.
- **Покупателей с номером не вида `+77XXXXXXXXX`: 0.** Новая проверка на экране входа никого не отрежет.
- Публичный API:
  - `POST` и `DELETE /me/avatar` без токена: 401;
  - `code_length: 5`: 422;
  - код из 5 цифр: 422;
  - коды из 4 и 6 цифр проходят проверку формата: `OTP_NOT_FOUND` на несуществующем номере.
- Настоящая запись на хостинг из контейнера, `FTPSMediaStorage`: тестовый WebP 158 868 байт, запись 1,48 с, удаление 0,69 с. Файл по HTTPS совпал по SHA-256, тип `image/webp`, после удаления файла нет.
- Папка `media/avatars/` создана, список файлов закрыт: 403.

Сумма 2,2 с значительно меньше таймаута приложения 15 с, поэтому риск ложной ошибки при обычной работе хостинга снят. Точка замера одна.

## Откат

```bash
docker tag cashback-backend:rollback-avatar-20261101T084801Z cashback-backend:local
docker compose up -d --no-build --force-recreate backend
```

Новый backend работает со старыми APK, откат нужен только при сбое. Столбец `avatar_url` старому образу не мешает. `expected_alembic_head` в старом образе ждёт `0010`, поэтому `/health/ready` после отката покажет расхождение версии: чтобы его снять, сначала выполнить `alembic downgrade 0010_customer_app_content` из нового образа. Откатывать базу после появления настоящих фото нельзя без потери ссылок на них.
