# Cashback One — контекст для Claude

Отвечай пользователю по-русски, коротко сообщай статус после каждого шага.

## Что это за проект

Программа лояльности (кешбэк-баллы) для магазинов на кассовой программе **POSCENTER ONE** (1С:Предприятие 8.3).
1С — единственный источник правды по картам, балансам и операциям; облако хранит их зеркало.

| Часть | Папка | Состояние |
|---|---|---|
| Облачный сервер (FastAPI + PostgreSQL + Redis) | `backend/` | работает на VPS: https://api.cashback-qr.poscenter.kz |
| Админка (React) | `admin/` | работает: https://cashback-qr.poscenter.kz |
| Приложение покупателя (Expo / React Native) | `mobile/` | демо: https://cashback-qr.poscenter.kz/demo/ , APK: https://cashback-qr.poscenter.kz/app/cashback-one-1.0.0.apk |
| **Windows-агент** (читает 1С через COM, шлёт в облако) | `agent/` | каркас готов, **связки с 1С нет** — это задача этой машины |

Документация: `docs/` (главное для этой машины — `STAGE0_WINDOWS_RUNBOOK.md`, `ONE_STAGE0_REQUIRED.md`,
`AGENT_ARCHITECTURE.md`, `AGENT_API.md`, `STAGE0_PENDING.md`).

## Зачем проект на этом компьютере (Windows)

Здесь есть 1С с базой POSCENTER ONE. Нужно связать агента с 1С. Всё остальное (сервер, админка,
приложение) уже сделано на Mac — их здесь не трогать без прямой просьбы пользователя.

### Шаг 1. Stage 0 — разведка структуры базы ONE (только чтение)

Строго по `docs/STAGE0_WINDOWS_RUNBOOK.md`:
1. Python 3.11+, venv, `pip install -e agent` и `pip install pywin32`.
2. Платформа 1С 8.3 с зарегистрированным `comcntr.dll` (`regsvr32`, нужны права администратора — попроси пользователя).
3. Отдельный пользователь 1С **только с правами чтения** — его создаёт пользователь/админ 1С.
4. `ONE_CONNECTION_STRING` задаётся только переменной окружения (без флагов CLI, без печати, без коммита).
5. `python -m poscenter_loyalty_agent.main stage0 check-environment`, затем `stage0 probe-metadata`.
6. По `stage0_output/metadata_inventory.md` найти и подтвердить настоящие имена объектов 1С по чек-листу из
   `docs/ONE_STAGE0_REQUIRED.md`: карты (штрихкод 13 цифр, телефон, ФИО, блокировка, версия изменений),
   регистр баланса (измерение карта, ресурс баланс), источник операций (уникальный ключ, время, тип
   начисление/списание, сумма, баланс после, чек, магазин). Если есть — сумма покупок для уровней (`spend_total`).
7. Собрать `stage0_output/stage0_mapping.json` по образцу `agent/stage0_mapping.example.json` и пройти
   `stage0 validate-mapping ... --require-verified`.

### Шаг 2. Настоящий COM-адаптер (TASK-009)

Реализовать чтение карт и операций из 1С в `agent/src/poscenter_loyalty_agent/one_com.py` / `source.py`
только по подтверждённому маппингу: дельта-выгрузка, непрозрачный курсор без ПДн и секретов, тесты на
фейковом провайдере. Режим `ONE_ADAPTER_MODE=com`.

### Шаг 3. Запуск агента против боевого облака

- Ключ агента создаёт суперадмин в админке (раздел агентов) — ключ показывается один раз; не печатать его в логах/чате.
- `AGENT_CLOUD_BASE_URL=https://api.cashback-qr.poscenter.kz`, `AGENT_ENV=production`.
- Сначала прогон в консоли (`poscenter-loyalty-agent run`), проверить в админке, что карты и операции пришли,
  потом установка как служба Windows (`windows_service.py`) и проверка старта/рестарта.

### Шаг 4 (после агента). Касса POSCENTER Cash

Нужна доработка кассовой программы POSCENTER Cash (делают её разработчики, не программист ONE). Cash передаёт
бонусные операции в ONE только при закрытии смены, поэтому баланс в приложении обновляется после закрытия смены:
- кассир сканирует QR/штрихкод; статичный штрихкод (пластик, Wallet) = номер карты, облако не нужно;
  динамический QR `C1…` касса отправляет в `POST /agent/qr/resolve` и получает номер карты; дальше начисление
  или списание выполняет касса как обычно; кодов из WhatsApp нет. Бонусные операции попадают в ONE через
  Документ.ОтчетКассовойСмены.

## Жёсткие правила

- **1С только на чтение.** Никаких записей, проведения документов, изменения справочников/регистров.
- **Никаких угаданных имён объектов 1С** в коде агента — только подтверждённые в Stage 0.
- Секреты (строка подключения 1С, ключ агента, пароли) — только в переменных окружения или локальных
  файлах вне git; не выводить в чат, логи, отчёты. `stage0_output/` в git не коммитить (он в `.gitignore`).
- Персональные данные покупателей (телефоны, ФИО) не попадают в отчёты, маппинг и курсоры.
- **Не пушить на GitHub** — коммиты только локальные, пока пользователь не скажет иначе.
- Не менять `backend/`, `admin/`, `mobile/` и не деплоить сервер с этой машины без прямой просьбы.
- Перед изменением кода агента прогоняй его тесты (`python -m pytest agent/tests`), после — снова.
  Если тесты красные ещё до твоих правок — остановись и сообщи пользователю, не чини молча.
- Шаг 4 (конфигурация 1С) сам не делай: это работа программиста 1С, ты только сверяешь контракт `docs/AGENT_API.md`.

## Подводные камни Windows

- **Разрядность:** Python и `comcntr.dll` должны совпадать (x64 с x64, x86 с x86), иначе COM-объект не создаётся.
- **Кириллица в путях:** профиль пользователя и папка проекта содержат кириллицу. Если venv, pip или служба Windows
  ломаются на путях — создай venv и `stage0_output/` в ASCII-пути (например `C:\cashback-venv`) и сообщи об этом.
- Регистрация `comcntr.dll` и установка службы требуют прав администратора — проси пользователя.
- Долгие шаги (ожидание прав, создание пользователя 1С) — сообщай статус один раз и жди, не опрашивай.
